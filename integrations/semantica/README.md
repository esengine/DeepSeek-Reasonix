# intelifar Semantica 隔离适配层

本目录是可选的本地语义资产体检桥接层。它不替代 intelifar 的数据库、权限、Wiki 或图存储，也不运行网络服务。

部署时检出 `semantica.lock.json` 指定的官方提交，并设置：

```text
INTELIFAR_SEMANTICA_ENABLED=true
INTELIFAR_SEMANTICA_PYTHON=C:\path\to\python.exe
INTELIFAR_SEMANTICA_SOURCE_PATH=C:\path\to\semantica-v0.6.0
```

Node 网关通过标准输入发送已完成权限过滤的最小 JSON，桥接器只把一条 JSON 结果写到标准输出。不要在这里读取 `apikey.txt`，也不要把证据全文、会话或密钥加入契约。

上线前必须核对 `git rev-parse HEAD` 等于锁文件中的提交。官方 `v0.6.0` 是未签名的 annotated tag，因此生产环境应从企业批准的镜像或制品库分发已校验源码，不能在每次启动时在线拉取。

当前验证环境为 Python 3.12；网关使用 `python -I -X utf8` 隔离启动，只加载源码中的去重、冲突和来源链模块，不安装 Semantica 的完整默认依赖。运行路径必须是单一绝对路径。

检查接口仅限空间所有者和管理员，每账号每分钟最多 3 次；单次最多 100 项资产、每项 20 条依据定位、15 秒超时。检查结果会以工作空间隔离的复核候选保存在 intelifar SQLite 中，正式资产和 Wiki 不会因此改变。

每个候选使用规范化业务字段生成稳定指纹。相同候选再次检查只更新最近发现时间，不重复创建、也不重新打开已经处理的记录；关键值变化时会生成新的候选。仅保存经过字段白名单和长度限制处理的资产编号、标题、来源名称、日期、置信度和判断理由，不保存原文、证据摘录、会话或密钥。

人工决定只有“确认需治理”和“保留独立记录”两种终态，只允许当前工作空间的所有者或管理员提交。决定与对应操作记录在同一个数据库事务中保存，提交后不能在界面中直接改判。已有候选的查询和处理不依赖 Semantica 进程持续在线；正式内容变化仍需使用 intelifar 的人工治理与审批流程。
