# 协作方式与事实驱动执行

Reasonix 桌面端输入框左下角的菜单包含两条互相独立的协作轴：

- **计划模式**：要求模型先产出计划，确认后再切换到实施。
- **目标模式**：给 Reasonix 一个目标，让它持续推进直到完成、阻塞或停止。

计划模式和目标模式属于“协作方式”轴，通常二选一。没有自动任务模式，也没有可选的质量底线。普通请求统一采用标准执行行为。
普通请求一律进入 executor；Planner 只响应显式 Plan、批准边界和 Goal 启动。
模型负责执行验证要求并判断完成；宿主展示实际执行事实。

## 计划模式

计划模式适合在动手前先确认方案。批准前，宿主强制禁止写入，包括完全权限、代理工具和子 agent；批准后按普通任务执行，模型更新待办并判断完成。验收说明作为任务上下文，不再要求逐步证据签收。它不是权限边界：规划期间的任何工具调用仍由当前“仅可查看／工作区内修改／完全权限”、权限规则与沙箱决定；`complete_step` 等显式执行阶段工具会等到计划批准后。

### 怎么开启

- 点击输入框左下角的“协作方式”按钮，选择“计划”。
- 也可以使用 `Shift+Tab` 切换计划模式。
- 开启后输入框下方会显示“计划”标签；点击该标签或再次使用 `Shift+Tab` 可退出。

### 建议使用场景

- 你还不确定实现方案，希望先看 Reasonix 的拆解。
- 改动范围可能跨多个文件、模块或配置。
- 需要先评估风险、测试面、兼容性或发布影响。
- 你希望先让 Reasonix 阅读代码和文档、给出方案，再决定是否继续实施。

### 注意事项

- 计划模式不是“自动完成任务”。它会先暂停在计划阶段，等待你确认。
- 计划模式通过模型指令和确认步骤减少误改风险，但不替代权限模式、`deny` 规则或沙箱。
- 如果你已经明确要直接改一个小问题，普通模式通常更快。
- 计划批准前保留写入门禁；批准后不再建立宿主质量义务。
- 计划模式只控制“先规划再执行”的流程；验证义务来自实际写入和批准后的合同。
- 需要技术上严格只读时，应使用“仅可查看”权限；Plan 只约束协作流程。

## 目标模式

目标模式适合给 Reasonix 一个更长线的目标，让它持续推进。目标启动后，Reasonix 会围绕该目标工作，直到任务完成、遇到阻塞、被你停止，或需要你确认关键决策。

### 怎么开启

- 点击“协作方式”按钮，选择“目标”。
- 如果输入框里已有文字，选择“目标”会把当前文字作为目标启动。
- 如果输入框为空，选择“目标”后会进入目标输入状态，输入目标并发送即可启动。
- 开启后输入框下方会显示“目标”标签；点击该标签可退出目标模式。

### 建议使用场景

- 你希望 Reasonix 连续完成一组相关步骤，例如“修复这个问题并补测试”。
- 任务需要探索、实现、验证多个阶段。
- 你希望减少中途反复下指令，让 Reasonix 在目标范围内持续推进。
- 目标明显是长周期研究、排障或优化，例如“持续排查直到根因明确”“彻底实现并验证”
  “不要原地打转”。Goal 默认持续执行，不会因为固定轮数或无进展计数而暂停。

### 推荐目标写法

复杂目标可以写成一份任务合约：Context、Request、Output format、Constraints、Pause policy。
Goal 模式会把这些部分当作任务边界；除非下一步涉及不可逆或对外可见操作、任务范围变化，
或需要你提供信息，否则会继续完成任务后再汇报。完整模板见
[`TASK_CONTRACT.zh-CN.md`](./TASK_CONTRACT.zh-CN.md)。

### 注意事项

- 目标要写得具体。推荐包含范围、成功标准和限制，例如“只改桌面端输入栏，补前端测试，不改后端协议”。
- 目标模式不是跳过审批。遇到高风险操作、权限限制、阻塞或需要产品判断时，仍可能停下来询问。
- 如果目标过大或边界不清，Reasonix 可能需要更多探索轮次，也会消耗更多 token。
- 普通聊天不会因为目标文本看起来复杂或长周期而自动切换模式。只有明确选择“目标”或使用
  `/goal` 后，Reasonix 才会进入 Goal；旧简单/写入/研究参数仍可解析，但不再改变额度。
- Goal 没有默认轮数、turn 数或时间上限。`--max-steps`、正数时间/成本预算仍可由用户显式选择。
- 旧 `.reasonix/autoresearch/...` 目录不会被新版本创建或改写；显式引用旧任务路径时只会读取并恢复成普通 Goal。
- 目标模式和计划模式是同一协作轴。切到计划模式时，会退出目标草稿/目标显示状态。

## 执行事实与模型声明

普通任务在模型正常结束后结束，不因未完成待办、文件数、敏感路径或缺少测试而自动续跑。
用户和项目的验证要求仍进入任务上下文。Goal 正常结束时接受模型的 `complete` 声明；
`blocked` 停止续跑；`continue` 或漏报继续活动目标，不调用独立 evaluator。
恢复和分叉只加载 Goal，显式启动或恢复后才允许自动续跑。

权限、沙箱、取消、显式预算和用户输入优先保持有效。测试失败、退出码、中断和检查后的修改
如实保留；模型完成声明不代表宿主认证，也不自动修改待办。详见
[执行语义与迁移说明](EXECUTION_MODEL_SIMPLIFICATION.md)。

## 协作方式如何组合

| 组合 | 是否支持 | 说明 |
| --- | --- | --- |
| 普通 | 支持 | 日常聊天与问答；低风险任务零辅助模型调用。 |
| 计划 | 支持 | 先用完整工具面研究并确认方案，再执行。 |
| 目标 | 支持 | 持续推进明确目标；Goal 启动可调用一次独立 Planner，之后根据模型报告续跑或停止。 |
| 计划 + 目标 | 不建议同时使用 | 两者都是协作方式轴，切换计划会退出目标草稿/目标显示状态。 |
| 工具权限（仅可查看／工作区内修改／完全权限）+ 任一组合 | 支持 | 权限运行时统一控制工具与沙箱边界。 |

工具权限的详细区别和使用场景，见 [`TOOL_APPROVAL_MODES.zh-CN.md`](./TOOL_APPROVAL_MODES.zh-CN.md)。

## 推荐选择

- **不确定怎么选**：保持普通模式；普通请求进入 executor，模型按任务要求判断检查范围。
- **成本敏感或简单问答**：直接提问即可——普通请求不会自动调用 Planner。
- **担心 Reasonix 改错**：开启计划模式先确认方案，并使用“仅可查看”或合适的工作区边界。
- **想让 Reasonix 持续推进一个明确目标**：开启目标模式，目标写清楚成功标准。
- **看重最终质量**：无需另选模式——明确写出需要的检查；结果面板如实展示执行记录。
