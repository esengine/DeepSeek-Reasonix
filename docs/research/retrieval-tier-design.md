# 分级检索系统设计（Retrieval Tier Design）

> 状态：v1 设计 · 2026-08-03 · dev/clearnature
> 目标：把 DeepSeek 服务端 web_search 从"单轮问答工具"升级为**情报级信息流模型**（OSINT 模式），
> 兼顾成本（本地缓存命中零 API）与质量（分级检索 + 可信度过滤 + 动态事件追踪）。

---

## 1. 总架构：四层漏斗 + 三个门控

```
用户提问
  │
  ▼
┌─ 门控 0：本地命中（零成本）──────────────────────┐
│  L1 精确（SHA-256） / L2 语义（Dice ≥ 0.35）    │
│  未命中 → 门控 1；命中 → 时效性判断             │
└────────────────────────────────────────────────┘
  │ 命中且新鲜 → ✅ 直接返回（零 API）
  ▼ 命中但时效敏感已过期 → 增量更新（单轮 web_search）
  未命中 / 需增量
  ▼
┌─ 门控 2：检索难度分级 ──────────────────────────┐
│  simple   （单事实查询）     → web_search 1 轮   │
│  general  （多事实组合）     → web_search 2-3 轮 │
│  complex  （多源交叉验证）   → architect-research │
│  deep     （课题级研究）     → deep-research 子代理│
└────────────────────────────────────────────────┘
  ▼
┌─ 门控 3：信息质量过滤 ──────────────────────────┐
│  可信度评分（来源白名单 / 交叉验证 / 垃圾剔除） │
│  场景覆盖检查 / 时效标签                        │
└────────────────────────────────────────────────┘
  ▼
落盘缓存（fresh_until + credibility + tier）→ 下次门控 0 命中
```

---

## 2. 门控 0：本地命中（已落地 L1/L2）

| 层 | 键 | 命中条件 | 成本 |
|----|-----|---------|------|
| L1 | SHA-256(query) | 完全相同 | O(1) 磁盘读 |
| L2 | 字符集 Dice 系数 | ≥ 0.35（近义改写） | 全量扫描缓存目录 |

已有：`LoadKnowledge` / `LoadKnowledgeSemantic` / `SaveKnowledge`（`knowledge.go`，4 提交）。

**升级点（P1）**：命中后新增**时效性判断**——不是所有命中都直接返回。

---

## 3. 门控 1：时效性判断（P1，本阶段实施）

### 3.1 数据模型扩展

```go
type KnowledgeEntry struct {
    Query         string    // 原始问题
    QueryHash     string    // SHA-256 键
    AnswerSummary string    // 蒸馏摘要
    KeyFacts      []string  // 核心事实
    Sources       []Source  // 来源（含可信度）
    TotalTokens   int       // 消耗记录

    // P1 新增：
    TimeSensitive bool      // 是否时效敏感（新闻/行情/事件）
    FreshUntil    time.Time // 时效截止（TimeSensitive=true 时有效）
    Tier          string    // 检索难度：simple/general/complex/deep

    CreatedAt     time.Time
    ExpiresAt     time.Time // 硬过期（默认 7d，非时效类用）
}
```

### 3.2 命中决策表

| 场景 | TimeSensitive | now < FreshUntil | 动作 |
|------|--------------|------------------|------|
| 事实类缓存 | false | -（用 ExpiresAt） | ✅ 直接返回（零 API） |
| 时效类未过期 | true | 是 | ✅ 直接返回（零 API） |
| 时效类已过期 | true | 否 | ⚠️ 返回缓存 + **标记 stale，触发增量更新** |
| 硬过期 | 任意 | ExpiresAt 已过 | 删除，走门控 2 |

### 3.3 增量更新策略

- 时效类过期：**复用原问题**走一次 web_search（单轮），合并新旧结果
- 增量结果落盘时**更新 FreshUntil**（滑动窗口），保留历史 event_chain

## 4. 门控 2：检索难度分级（P2）

### 4.1 难度判定

```go
type RetrievalTier string

const (
    TierSimple  RetrievalTier = "simple"   // 单事实：天气/人口/日期
    TierGeneral RetrievalTier = "general"  // 多事实组合：对比/总结
    TierComplex RetrievalTier = "complex"  // 多源交叉：政策影响/事件分析
    TierDeep    RetrievalTier = "deep"     // 课题级：深度研究/报告
)
```

判定方式：LLM 单轮分类（复用 json_schema，`retrieval_tier` 字段）或启发式（问题长度/关键词）。

### 4.2 路由表

| Tier | 执行器 | 轮次上限 | 产出 |
|------|--------|---------|------|
| simple | web_search 1 轮 | 1 | 摘要 |
| general | web_search + 追问 | 3 | 摘要 + 多来源 |
| complex | `architect-research` 编排 | 5 | 交叉验证报告 |
| deep | `deep-research` 子代理 | 12（loop-engineer 上限） | L1/L2/L3 分级报告 |

## 5. 门控 3：信息质量过滤（P3）

### 5.1 可信度评分（0-1）

| 信号 | 权重 | 来源 |
|------|------|------|
| 专业站点白名单（`sources.md` 已验证 A/B 级） | 0.4 | deep-research 技能 |
| 多源交叉验证（≥2 独立来源一致） | 0.3 | 检索结果 |
| 权威域（gov/edu/org 官方） | 0.2 | URL 规则 |
| 垃圾特征剔除（广告/引流/低质） | -0.1×命中数 | URL 黑名单 |

### 5.2 场景覆盖

- 时间跨度（近 24h / 近 7d / 长期）
- 地理/语言覆盖
- 立场多样性（至少 2 个独立信源）

### 5.3 事实核实（美伊战争情报模式）

动态事件追踪：
```
初始事件 → 后续更新（增量轮） → 冲突信号检测（矛盾来源）
→ 关联事件链接（event_chain） → 置信度随时间演化
```

## 8. 成本模型（冒烟测试实测基准）

| 路径 | token | 延迟 | 成本 |
|------|-------|------|------|
| 本地命中（L1/L2） | **0** | ~300µs | 零 |
| 简单检索（1 轮） | ~32K | ~27s | 一次 |
| 深度研究（12 轮） | ~400K+ | 分钟级 | 十二次 |

**核心优化目标**：把常见问题沉淀为本地命中，检索只发生在"新问题 + 时效增量"。

## 9. 价值观与道德护栏（2026-08-03 定稿）

Reasonix 本质是代码编程助手，检索是信息助手附加能力。开发者有社会责任，
立场**中立**：不是宽泛自由主义者（放任污染），也不是保守控制者（拦截屏蔽）。

### 原则

1. **不拦截、不训斥、不屏蔽** —— 检索结果永远完整返回，道德护栏只做
   "上下文重塑"：`PanicMode` 在灾难+时间紧迫查询后追加权威核实安抚行
   （`panicReassurance`，提交 `5288a3d0a`）。
2. **不追踪用户**（合规底线，法律要求）——`PanicScore` 只看当前问题文本，
   无状态；任何用户画像必须**用户明确提供或可拒绝**，绝无隐蔽收集。
3. **该提醒的已提醒** —— 官方应急渠道、权威核实、科学避险引导、心理安抚
   一次到位，不越界控制内容本身。
4. **功能覆盖要广** —— 作为信息助手，分级检索 simple→general→complex→deep
   覆盖日常查询到课题级研究；护栏始终中立，不因话题敏感而区别对待检索能力。

### 实现映射

| 护栏能力 | 位置 |
|---------|------|
| PanicScore（灾难×时间紧迫，无状态） | `quality.go` |
| PanicMode 破壁引导（显式开关默认关） | `retrieve.go` |
| EmotionHits / MarketingHits（内容安检） | `quality.go` |
| 可信度评分 + 垃圾剔除（P3） | `quality.go` |

### 核心设计原则

| 原则 | 体现 |
|------|------|
| AI 驱动前置 | LLM 拆解命题/判定场景语言/生成查询词 |
| 程序确定性后置 | 数据模型/拼图/置信度演化/缓存 |
| 本地优先省钱 | L1/L2 命中零 API（实测 305µs vs 27s） |
| 不静默联网 | Policy 授权 + 频率尺标 + WebBlocked |
| 中立护栏 | 不拦截不训斥，破壁引导 + 权威核实 |
| 污染免疫 | 白名单/营销/煽动/恐慌四重检测 + 安检落盘 |

### 规模指标

- 16 核心文件 + retrieve_info 工具 + 4 模式冒烟入口
- 159 提交 / 111 测试 PASS / lint 0
- 实测：霍尔木兹石油/农业 2 个真实主题检索成功
