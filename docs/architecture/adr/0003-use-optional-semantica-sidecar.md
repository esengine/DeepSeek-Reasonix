# ADR-0003：以可选隔离进程接入 Semantica 语义治理能力

## 状态

Accepted

## 日期

2026-08-11

## 背景

intelifar 已经以 SQLite 保存正式发布资产、Wiki 版本、关系状态和哈希审计链。Semantica 提供实体去重、来源冲突发现和来源链追踪能力，但其完整 Python 依赖栈、数据模型和发布节奏不应进入小微版在线网关的核心故障域，也不应成为正式数据源。

普通企业用户需要的是“哪些资产疑似重复、哪些责任信息需要复核、结果依据来自哪里”，而不是直接操作新的知识工程框架。语义计算还必须服从现有工作空间、角色和密级过滤。

## 决策

以可选、短生命周期的本地 Python 子进程接入 Semantica v0.6.0；Node 网关是唯一入口和权限执行点。

- 固定官方标签 `v0.6.0` 和提交 `9c9ab6a23fe67f1818bd94029f975c9db51247eb`；
- 只加载去重、冲突和来源链三个模块，不安装完整默认依赖；
- 子进程通过标准输入输出交换有大小上限的 JSON，不监听端口、不读取 API 密钥、不访问网络；
- 网关先按工作空间、角色和密级过滤已发布资产，再发送最小字段；不发送上传原文、完整证据引文、密码、会话或 API 密钥；
- 第一阶段只返回建议，不自动合并资产、不更新 Wiki、不确认关系；
- 结果不作为正式业务记录，管理员复核后仍使用 intelifar 既有治理动作；
- 超时、版本不符、依赖缺失或进程异常均显式降级为“语义增强不可用”，不影响文档分析、资产库、Wiki 和搜索；
- 默认关闭，只能由部署环境显式启用。

## 后果

### 正面

- 复用 Semantica 的语义治理能力，同时保留 intelifar 的权限、审计和正式数据边界；
- 不给核心网关增加 Python 常驻服务和新的网络攻击面；
- 可独立升级、回退或关闭，失败不会阻断主链路；
- 管理员看到业务化复核建议，普通岗位无需理解 Semantica 概念。

### 负面

- 每次检查存在子进程启动成本，因此限制为管理员主动运行和最多 100 项资产；
- 需要维护跨语言 JSON 契约、版本锁与本地 Python 运行环境；
- 字符串与属性相似度只生成候选，仍需人工确认，不能声称自动完成资产合并。

### 中性

- SQLite 继续是系统记录，关系投影继续可重建；
- 若未来需要持续大规模语义计算，可把相同契约迁移到受控作业服务，但权限过滤仍在 intelifar 侧完成；
- Semantica 许可证和版本信息只在管理员技术详情中展示。

## 备选方案

### 将 Semantica 直接导入 Node 网关主进程

拒绝。语言运行时不兼容，且会把可选依赖和异常传播到核心请求链路。

### 常驻独立 HTTP 服务

暂不采用。小微版会新增端口、鉴权、证书、监控和网络隔离责任，收益不足以抵消运维成本。

### 用 Semantica 替换 SQLite 或图投影

拒绝。Semantica 是计算与治理能力，不是 intelifar 的正式发布、版本和审计系统。
