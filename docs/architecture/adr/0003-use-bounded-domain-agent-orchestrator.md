# ADR-0003：采用受控领域 Agent 编排器

## 状态

Accepted

## 日期

2026-08-10

## 背景

intelifar 需要恢复原 Reasonix 面向复杂任务的自然语言规划与连续执行能力，但当前产品边界是企业文档 IP 智能和 Wiki。直接启动通用 coding agent 会同时引入 Shell、文件系统、通用 MCP、外部副作用和第二套会话/权限语义；只依赖提示词禁止这些能力不能形成企业服务所需的硬隔离。完全固定的工作流模板虽然安全，但无法覆盖用户多样的任务表述和组合分析需求。

## 决策

在现有 Node 同源网关内实现 Reasonix 语义的受控领域编排器：

- 使用任务契约规范目标、输出、约束和暂停条件；
- 使用规划器与执行器分离，DeepSeek 只产出受限计划和结构化结果；
- 只注册无通用副作用的 IP/Wiki 领域工具；
- 每次工具调用重新执行工作区与角色授权；
- 保存步骤收据，以证据门禁决定任务是否可交付；
- 对步骤数、调用数、上下文、耗时和失败重试做硬限制；
- Agent 只生成草案和建议，不发布、不删除、不共享、不保存 Wiki、不确认关系。

原 Reasonix Go 内核继续保留在仓库中，但不会作为 Web 产品的通用执行进程暴露。领域编排器复用其安全语义，而不是复用面向代码工作的工具集合。

## 后果

### 正面

- 自然语言可以组合资产搜索、证据核查、图影响分析和 Wiki 草案。
- 工具白名单和服务端校验形成可测试、可审计的能力边界。
- 复用现有认证、SQLite、资产可见性和审计链，无需增加常驻 Agent 服务。
- 固定结果契约和证据门禁降低模型输出不确定性。
- 未来可以在不改变 UI 契约的前提下替换队列、数据库或模型。

### 负面

- 不能直接使用 Reasonix 的通用插件和 coding 工具生态。
- 每新增一个领域动作都必须实现工具、权限规则、输入校验和验收测试。
- 计划与合成通常需要两次模型调用，增加延迟和 token 成本。
- 首期串行执行，不适合长时间或跨系统的自主流程。

### 中性

- Wiki 正式保存、发布、分享和关系确认继续由现有明确 UI 完成。
- 任务中断后需要用户重新提交，不自动恢复外部模型调用。

## 备选方案

### 直接暴露 Reasonix 通用执行器

拒绝。能力面超出文档 IP/Wiki，且会增加 Shell、文件、插件与外部调用的生产安全责任。

### 只使用固定任务模板

未采用为内核。可作为 UI 示例，但不能满足自然语言泛化。

### 独立 Agent 微服务

暂缓。小微企业单机版没有独立扩缩容需求；拆分会增加认证、网络、部署、备份和观测成本。多实例企业版可在保持 API 与任务契约不变的前提下迁移。
