## 提交记录

### 1. `09bbb13`：补全 OpenAI-compatible 根地址和 `/v1` 请求路径

- 问题：部分兼容供应商只提供根地址，客户端拼接请求路径时会产生错误 URL。
- 方案：在底层 URL 解析和请求路径构造处补全兼容的根地址规则。
- 逻辑：统一规范化 base URL，再由请求层负责追加版本和资源路径，避免 GUI 和 CLI 各自拼接。
- 结果：兼容供应商的请求路径契约更明确；没有把供应商地址写死到客户端。

### 2. `52df4e0`：让桌面端 key 验证使用配置中的网络代理

- 问题：桌面端验证 key 时没有沿用 provider 的代理配置，导致代理环境下误报网络失败。
- 方案：验证请求复用已加载的 provider 代理设置。
- 逻辑：配置读取和网络传输使用同一代理来源，减少“发送可用、验证失败”的分叉。
- 结果：代理配置进入 key 验证路径；未记录真实 key。

### 3. `f15d719`：首次启动缺少历史文件时按可恢复空历史处理

- 问题：首次启动没有历史文件时，加载流程把正常空状态当成异常。
- 方案：为缺少初始历史文件的场景建立明确的空历史结果。
- 逻辑：区分“尚未产生历史”和“已有历史但读取损坏”，避免错误恢复分支吞掉真实故障。
- 结果：首次启动可以进入空会话状态，损坏历史仍保留错误语义。

### 4. `33d97e6`：显式隔离 WebView2 profile

- 问题：桌面端 WebView2 profile 可能与其他运行实例混用，产生缓存和锁冲突。
- 方案：显式为运行实例派生独立 profile 路径。
- 逻辑：profile 跟随当前运行数据树，不依赖系统默认目录。
- 结果：桌面端可以在独立数据树中启动和关闭，减少跨实例污染。

### 5. `c3dcb79`：限制持久化工具输出

- 问题：工具输出无限增长会放大会话文件、恢复读取和后续上下文成本。
- 方案：在持久化边界增加有界输出策略。
- 逻辑：控制写入规模，同时保留工具调用的可恢复结构，避免只在 UI 侧截断。
- 结果：持久化输出有明确上限，后续 event log 和恢复逻辑可以继续审查。

### 6. `df51e20`：区分并脱敏 provider transport 错误

- 问题：DNS、TLS、代理、超时、URL 和普通网络错误混在一起，且原始错误可能泄露敏感细节。
- 方案：在传输错误边界分类并脱敏。
- 逻辑：保留排障所需的错误类别和状态，不把 key、完整敏感 URL 或请求内容带入用户报告。
- 结果：GUI 和 CLI 能获得稳定的错误类别，日志边界更安全。

### 7. `fe63581`：修复 WebView2 smoke 测试清理可靠性

- 问题：冒烟测试结束时残留 profile 或进程会造成下一次验收不稳定。
- 方案：加强测试清理和退出等待。
- 逻辑：清理动作与进程生命周期绑定，失败时保留可诊断状态。
- 结果：原生 WebView2 smoke 清理回归通过。

### 8. `1c6aac1`：首次启动空白 tab 返回合法空历史

- 问题：新建空白 tab 的历史响应可能为非法空值，侧栏和桥接层无法统一处理。
- 方案：返回结构合法的空历史对象。
- 逻辑：让首次启动和普通历史加载共享数据契约，而不是让前端猜测 `null` 的含义。
- 结果：首次启动空白 tab 可以稳定显示空状态。

### 9. `cae31e7`：流式 POST 已写出后连接失败时禁止透明重放

- 问题：请求正文已经写出后发生连接错误，透明重试可能造成供应商侧重复请求。
- 方案：根据请求是否已经写出区分可重试和不可透明重放的错误。
- 逻辑：优先保证一次性副作用请求不被客户端隐式复制。
- 结果：流式请求失败不会被错误重放，调用方可以获得明确失败状态。

### 10. `87c1414`：恢复 event-log divergence 测试夹具

- 问题：测试夹具使用相同 checkpoint 时，新增事件可能被错误掩盖。

- 逻辑：让测试同时验证 checkpoint 和后续 event 的差异，而不是只验证相同快照。
- 结果：事件日志分叉回归能够发现错误的恢复合并行为。

### 11. `e81e133`：新增只读源码更新检查
