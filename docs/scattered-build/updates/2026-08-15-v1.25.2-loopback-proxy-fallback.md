## 提交记录

### 本次提交：修复源码更新检查被已关闭的本机回环代理持续阻断

- 问题：Windows 进程可能继承仍指向本机回环地址的 `HTTP_PROXY`、`HTTPS_PROXY` 或 `ALL_PROXY`；代理进程关闭后，散装版启动检查会持续记录 `check-failed`，即使 GitHub 直连可用。
- 方案：把代理判定和子进程环境调整拆入独立 helper；首次检查仅在错误同时包含代理语义、回环地址和明确的连接拒绝时，清除该子进程的代理变量并重试一次。
- 逻辑：回退条件采用窄匹配，避免绕过用户仍在工作的代理配置。普通 DNS、TLS、鉴权、远端代理及其他网络错误不触发直连；重试结果增加 `proxyFallback=direct-after-loopback-refused`，便于审计。
- 结果：源码更新检查在失效回环代理环境下恢复为可用，同时保留其他网络错误的原始失败语义。部署只替换 PowerShell 适配脚本和 helper，本次未重编译桌面端或 CLI。
