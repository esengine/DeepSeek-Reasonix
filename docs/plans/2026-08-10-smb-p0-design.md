# intelifar 小微企业 P0 设计

## 目标与边界

本阶段把现有受控演示升级为可供单个小微企业长期试用的单机版本，覆盖真实账号、工作空间隔离、任务状态持久化以及 Wiki 可编辑版本链。假定一个部署服务一个或少量工作空间、1–50 名用户、单区域运行，并由磁盘加密和 HTTPS 反向代理保护主机。企业 OIDC、SCIM、复杂 ABAC、多区域容灾和独立搜索集群不在本阶段范围内，但所有数据接口都携带 `workspace_id`，为后续替换 PostgreSQL 和企业 IdP 保留边界。

## 方案比较

1. **SQLite 单机版（采用）**：使用事务数据库保存账号、会话、任务、发布、Wiki 版本和审计事件。部署简单、可在本地 E2E 中真实验证，适合售前和小微客户；限制是不能支撑多节点共享写入。
2. **直接 PostgreSQL**：最接近 SaaS 生产目标，但当前工作区没有数据库实例，会让本地交付与真实 E2E 依赖额外基础设施。
3. **继续原子 JSON**：依赖最少，但无法提供数据库约束、查询、角色隔离和可验证迁移，不满足本阶段目标。

SQLite 通过仓储模块封装，业务路由不拼接 SQL。未来 PostgreSQL 适配器只需要实现相同接口，前端和分析供应商客户端无需变化。

## 数据与安全设计

用户密码使用 Node `scrypt` 加随机盐保存；会话使用 256 位随机令牌，浏览器只收到 `HttpOnly`、`SameSite=Lax` Cookie，数据库只保存令牌 SHA-256。角色采用 Owner、Admin、Editor、Viewer 四级模型。所有分析、资产、Wiki、证据和搜索 API 在服务端取得当前会话，并将 `workspace_id` 传入仓储查询；未登录返回 401，权限不足返回 403。

分析任务每次状态变化写入 SQLite。上传文件使用服务端生成路径落入权限受限的运行目录；进程重启时，未完成任务标记为 `interrupted`，用户可以从保留文件重新执行。成功任务清理临时原件。Wiki 每次保存创建新版本，不覆盖历史内容；审计事件形成服务端哈希链。默认本机演示模式继续兼容现有 E2E，但生产环境没有引导凭据时拒绝启动。

## 失败模式与验收

- 数据库不可写：请求失败且不调用外部供应商。
- 进程中断：任务和上传文件保留，重启后显示可重试状态。
- 重复发布：数据库唯一约束返回同一发布记录。
- 跨工作空间 ID 猜测：查询返回不存在，不泄露对象元数据。
- Wiki 并发编辑：客户端提交基础版本；版本不一致返回 409，避免静默覆盖。
- 会话过期或用户停用：后续请求立即返回 401。

验收包含仓储单测、认证/RBAC API 测试、租户隔离测试、重启恢复测试、Wiki 版本冲突测试、浏览器登录与编辑 E2E、构建和凭据扫描。
