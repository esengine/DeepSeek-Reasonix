# intelifar 小微企业 P0-D 协作与安全分享设计

**日期：** 2026-08-10

**评分目标：** 单实例小微企业售前 MVP 超过 98/100

## 1. 产品缺口与完成口径

P0-C 已形成身份、持久任务、Wiki 版本、文件隔离、备份和运维闭环，但空间所有者仍无法自助邀请团队成员；生命周期页面创建的分享仅存在浏览器本地状态，不能真正到期、撤销或审计访问。这两处是从“可演示”进入“可由小微客户自助使用”的最大缺口。

P0-D 完成口径：owner/admin 能创建一次性邀请并管理非 owner 成员；受邀人能通过公开激活入口设置自己的强密码；服务端安全分享必须绑定真实工作空间资产，使用链接令牌和独立访问码双凭证，支持到期、撤销和访问审计；公开页面只能拿到脱敏 Wiki，不能返回原文、证据引用、工作空间或账号数据。

## 2. 成员生命周期方案

### 方案 A：管理员直接设置临时密码

实现最短，但管理员会接触成员凭据，临时密码还可能通过聊天或邮件明文流转，不采用。

### 方案 B：一次性邀请令牌（采用）

管理员输入企业邮箱、姓名和角色，服务端生成高熵令牌，只保存 SHA-256；令牌只在创建响应中显示一次。受邀人在有效期内打开激活页并设置 12–128 字符密码，服务端事务性创建用户并消费邀请。角色仅允许 admin/editor/viewer，禁止通过邀请创建 owner；禁止禁用或降级 owner，禁止当前用户禁用自己。禁用成员时同时撤销其全部会话。

### 方案 C：强制外部邮件/身份提供商

生产体验最好，但当前没有已授权的邮件域名或 IdP。P0-D 提供可复制的邀请链接和明确的“未配置邮件投递”状态，后续可插入邮件服务；大型企业仍走 OIDC/SCIM。

## 3. 安全分享方案

### 方案 A：浏览器本地分享记录

无法跨设备、撤销或审计，正是当前需要消除的模拟能力。

### 方案 B：单一能力链接

高熵链接能提供基础安全，但链接被转发后即可直接访问，不足以支撑对外 IP Wiki。

### 方案 C：链接令牌 + 独立访问码（采用）

创建时生成 256-bit 链接令牌和独立高熵访问码，数据库只保存二者哈希。链接打开后先显示锁定态和掩码邮箱，提交访问码后才返回脱敏 Wiki。公开访问按 IP/分享限流；过期、撤销和错误凭证统一返回最少信息。每次成功访问更新计数与时间，并追加服务端审计事件。

分享范围在本阶段固定为 `redacted-wiki`：只返回标题、执行摘要、关键机制、指标、关系和版本；不返回原始文档、逐字证据、解析预览、成员、审计或内部资产元数据。

## 4. UI 与信息架构

“系统状态”增加 Team Access 管理账本，采用现有 intelifar 工业化运维视觉：成员、角色、状态、邀请创建和禁用/启用操作集中呈现。生命周期页面的 Active Shares 改为真实服务端列表；创建后显示链接和访问码，并提醒必须分渠道发送。分享条目提供撤销操作和访问次数。

新增无侧栏的公开分享页，以“受控阅览室”为视觉方向：深色品牌门楣、文档纸张工作面、显式到期时间、访问码解锁、脱敏范围和水印提示。它不复用内部工作台会话，也不加载内部 API。

## 5. 威胁控制与边界

- 邀请、分享令牌和访问码不明文入库、不写审计、不进入列表 API。
- 所有管理读写均执行工作空间过滤和角色检查；公开 API 只能按高熵令牌哈希定位。
- 数据库语句参数化；角色、邮箱、有效期、ID 和 JSON 大小全部服务端校验。
- 邀请消费、成员状态修改、分享撤销和访问计数使用事务。
- 禁用成员立即撤销全部会话；邀请和分享撤销均不可恢复。
- P0-D 不冒充邮件投递、MFA、OIDC/SCIM 或法律意义上的 DRM；这些仍是后续连接器或部署责任。
