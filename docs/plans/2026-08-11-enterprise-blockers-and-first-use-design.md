# 企业岗位阻断与首次使用优化设计

## 背景与目标

本设计以 `artifacts/enterprise-first-use-audit-2026-08-11/report.md` 为已确认输入。目标是消除只读成员审计越权和上传假成功两个 P0，并降低管理员、编辑者、阅读者和外部接收方第一次使用时的技术理解成本。

## 方案比较

1. **只隐藏前端按钮**：改动最小，但用户仍可直接调用接口，不能解决审计数据泄露，拒绝。
2. **服务端权限收紧 + 前端能力裁剪 + 状态机修正**：同时保证安全边界和界面真实性，改动集中在现有路由、页面和行为脚本，采用。
3. **重建细粒度 ABAC、审批流和脱敏工作流**：长期更完整，但需要新数据模型、策略中心和迁移，不属于本轮阻断修复。

## 架构与数据流

- 全空间审计读取由 `viewer` 调整为 `admin`（owner/admin）；写入受控 UI 审计事件仍允许 viewer，以保留访问留痕。
- 前端从当前会话派生 `canAnalyze`、`canReview`、`canAudit`、`canOperate`。无权限入口隐藏或禁用，并显示常驻中文说明；路由和提交处理器再次校验。
- 真实文档提交在服务端返回 202 前不改变分析状态、不跳页、不显示成功；403 被翻译成业务中文。服务端接收后才创建新的任务状态，并清除旧任务标识。
- Wiki 编辑保存基线快照，输入变化实时生成预览；没有内容变化时禁止保存。服务端再次比较持久化内容，拒绝无变化版本。
- Agent 结果仍由既有证据门禁约束；界面隐藏内部 ID、移除工程术语。服务端用本次收据中实际可展示的资产数纠正摘要里的“共 N 项”表达。

## 体验优化

- 资产库两个入口统一进入真实文档接入，明确“资产由证据文档提取”。
- “脱敏与溯源工作台”改为“敏感信息与风险线索”，不承诺当前没有的正式涂黑交付。
- 生命周期把资产待确权和关系待复核分别展示。
- 分享、外部页、系统状态和 Agent 改为业务中文；技术细节放入可展开区域或辅助说明。
- 撤销分享明确只阻止后续访问，已加载或复制内容无法召回。

## 错误处理与安全

- 前端对 401 锁定工作空间，对 403 显示当前岗位无权限，不泄露服务端英文错误。
- 后端权限是最终边界，前端隐藏不作为安全控制。
- 审计 CSV 仅从管理员已获授权的数据生成。
- 无变化 Wiki 请求返回 409，不产生新版本或审计事件。

## 验收

- viewer 请求 `GET /api/audit` 返回 403；owner/admin 返回 200。
- viewer 看不到审计导航和导出，不能打开接入对话框；强制提交不改变当前分析状态。
- editor 上传成功路径保持可用。
- Wiki 无变化不可保存，服务端直接请求也不能产生版本。
- Agent 不再显示 Reasonix、工具调用、交付门禁、内部来源 ID；数量口径与收据一致。
- 资产、风险、生命周期、分享、外部页和系统状态文案与真实能力一致。
- 单元、契约、模块 E2E、Agent E2E、真实 UI E2E、构建全部通过，并保留修复后截图。
