# Windows 原生全量 Go 测试设计

## 目标

在不安装、启动或调用 WSL，也不依赖 Docker 的前提下，让 Windows 开发机能够可靠执行仓库的三个 Go module 全量测试：根 Reasonix、`sdk/go` 与 `desktop`。测试必须覆盖真实用例，不通过扩大超时、跳过测试或替换产品逻辑来隐藏平台问题。

## 已确认的阻塞原因

当前 Windows 环境存在两个彼此独立的问题：

1. `bash` 默认解析到 `C:\Windows\System32\bash.exe`，这是 WSL 启动器；仓库的打包与语料测试需要的是 POSIX Bash。机器已经安装 Git for Windows，因此应显式使用其 `bin\bash.exe`。
2. Windows Defender 防火墙允许已登记的 `node.exe` 接收入站连接，但会阻止 Go 测试临时编译出的可执行文件访问自己创建的 loopback HTTP 服务。桌面端快速点击测试的模拟 LLM 服务因此无法返回，表象为控制器持续运行；这不是产品并发锁泄漏。

根模块的可选真实供应商缓存守卫还会调用外部 DeepSeek。它不属于默认离线全量测试，并会把供应商波动混入单元/集成测试结果；原生入口只在自身进程中移除该可选开关，不读取或修改真实 API 密钥。

## 方案

新增一个 PowerShell 原生测试入口。入口先完成只读预检：定位仓库、Go 1.26.5 和 Git Bash，验证 Bash 不来自 `System32`，并创建结果目录。非管理员启动时，它通过 Windows UAC 启动一个最小权限职责的防火墙租约代理；全量 Go 测试仍在原来的普通用户进程执行，确保权限、沙箱和文件锁行为具有代表性。

提升权限只用于创建两条生命周期受控的防火墙规则：

- IPv4：本地地址与远端地址都严格限定为 `127.0.0.1`；
- IPv6：Windows 防火墙拒绝把 `::1` 作为显式地址过滤器，因此规则严格绑定接口索引 1 的 IPv6 loopback adapter，不匹配任何局域网或公网接口；
- 协议仅为 TCP，方向仅为入站，不开放局域网或公网访问；
- 规则名包含本次运行的唯一标识，并由代理在 `finally` 中按精确名称删除；父进程结束或超过租约上限也会触发回收。

入口把 Git for Windows 的 `bin` 目录放到当前子进程 PATH 最前，设置 `GOTOOLCHAIN=local`、可用的 Go 模块代理和 `GOFLAGS=-buildvcs=false`，然后以 `-count=1` 禁用测试缓存，依次执行：

1. 根 module：`go test -p 4 -count=1 -timeout=8m ./...`；
2. SDK module：`go test -p 4 -count=1 -timeout=8m ./...`；
3. Desktop module：`go test -p 1 -count=1 -timeout=12m ./...`。

即使其中一个 module 失败，入口仍继续执行其余 module。每个 module 保存独立日志，最后生成 Markdown 汇总并返回非零退出码。Desktop 使用包级串行以降低 Windows 文件句柄释放和调度噪声，但不会禁止测试内部并发，也不会减少覆盖范围。

## 选择理由

相较于把所有 Go 测试可执行文件永久加入防火墙，loopback-only 临时规则不依赖随机二进制路径，权限范围更小且可自动恢复。相较于修改测试使用固定端口或延长等待，它直接修复本机网络前提，保留测试原有语义。相较于 WSL 或 Linux 容器，它验证的正是最终 Windows 桌面交付所依赖的文件锁、路径、签名脚本与进程行为。

## 安全与失败恢复

- UAC 提示让系统级变更保持显式可见；预检模式不需要管理员权限，测试进程也不会继承管理员权限。
- 防火墙规则只允许本机回环，且不读取 `apikey.txt` 或输出环境密钥。
- 所有规则删除都在 `finally` 中执行；删除失败会被写入报告并导致整次运行失败。
- 入口结束后再次查询精确规则名，确认没有残留。
- Git Bash、Go 或管理员权限不可用时快速失败，并给出可操作错误，不回退到 WSL。

## 验收标准

- 预检明确报告 Go 路径、版本与 Git Bash 路径，Bash 绝不来自 `C:\Windows\System32`。
- 三个 Go module 均实际执行全量、禁缓存测试，并分别产生日志。
- 先前失败的 loopback HTTP、桌面快速点击和 Bash 打包测试通过。
- 测试结束后两条临时防火墙规则均不存在。
- 汇总报告记录每个 module 的命令、耗时、状态和日志位置，入口最终退出码与总体结果一致。
