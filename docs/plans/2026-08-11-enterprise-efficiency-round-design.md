# 小微企业效率优化轮次设计

## 目标

在不引入复杂工单系统或表格式编辑器的前提下，缩短企业员工处理资产治理待办和查找 Wiki 的时间，并让每项待办明确由哪个岗位负责、建议何时完成。

## 方案选择

批量资产治理比较了三种方案：资产表格多选、行内编辑、引导式批量弹窗。选择引导式批量弹窗：待办中心直接打开弹窗，默认勾选全部待确权资产，用户可取消不属于同一部门或密级的项目，再一次确认共同的权属部门和敏感级别。该方案移动端可用、操作步骤少，也不会让资产库演变为复杂编辑器。逐项详情仍保留现有“完善资产信息”入口。

待办责任采用岗位负责制而非个人工单分派。小微企业通常岗位少、成员会兼岗，持久化个人指派、转派和催办会增加管理负担。系统根据事项类型显示“负责岗位”和“建议今天完成/建议三天内完成”，并保留真实业务状态作为待办来源。

搜索使用确定性相关度排序，不引入新的向量服务。Wiki 标题精确匹配优先，其次为标题、摘要、核心机制、标签、来源文档和原文依据；相同分数按发布时间与标题稳定排序。用户仍能看到命中位置和片段。

## 数据与权限

- 批量接口仅允许知识编辑者、空间管理员和空间所有者调用。
- 单次最多同步 50 条来源记录；合并展示的一项独立资产会同步其全部来源记录，所有记录必须属于当前工作空间。
- 权属部门不能为空，也不能继续使用“待确权/待认领/待复核”。
- 密级只能是“公开、内部、机密”。
- 批量更新在一个数据库事务内完成；任一资产不存在或输入无效时全部回滚。
- 成功后重新投影资产关系网络，并写入一条批量操作记录。
- 只读成员看不到修改入口，调用接口返回 403。

## 交互与状态

批量弹窗包括资产选择列表、已选择数量、权属部门、敏感级别、确认影响说明和错误区域。必须至少选择一项资产。提交期间按钮进入忙碌状态；成功后关闭弹窗、刷新资产、全景网络、待办和操作记录。失败时保留用户输入，不产生部分更新。

## 验收

- 存储测试覆盖批量成功、跨空间回滚、无效输入和操作记录。
- API 测试覆盖编辑者成功、只读成员拒绝和最多 50 项限制。
- 浏览器 E2E 覆盖两项待确权独立资产、三条来源记录的勾选、统一更新、待办消失和只读边界。
- 搜索测试覆盖标题结果优先于正文/证据结果。
- 真实 UI 只打开批量弹窗并取消，不替客户填写真实权属。
