# intelifar 小微企业 P0-C 安全运维设计

**日期：** 2026-08-10

**范围：** 上传安全隔离、SQLite 可验证备份、管理员运行状态与失败任务重试

## 1. 目标与验收口径

本阶段补齐售前 MVP 和小微企业单机版上线前最直接的三项运维闭环：不可信文件在进入 MinerU 前完成安全决策；运行库可以在线生成并验证备份；空间管理员可以从真实 UI 看到扫描、备份、审计与任务状态，并安全重试可恢复任务。

验收时必须满足：恶意测试样本不会调用 MinerU 或 DeepSeek；备份由 SQLite 在线备份能力生成且通过 `PRAGMA integrity_check`；备份和重试接口仅 owner/admin 可操作；真实浏览器可完成登录、查看运行态、创建及复核备份、重试失败任务并留下截图。

## 2. 文件安全方案选择

### 方案 A：只做文件扩展名和 Magic Number 校验

实现简单，但无法识别 EICAR、Office 宏、压缩炸弹和 ZIP 内嵌可执行内容，只适合作为上传格式校验，不足以称为安全扫描。

### 方案 B：强依赖 ClamAV

检测能力更完整，但当前开发机没有 ClamAV；将其设为唯一实现会让本地 MVP 无法运行，也无法覆盖第三方扫描服务场景。

### 方案 C：分层扫描适配器（采用）

先执行不依赖外部服务的确定性预检，再按配置调用 ClamAV 或其他外部扫描器。内置预检拦截 EICAR、伪装 PE、Office 宏、高风险 ZIP 条目和压缩炸弹指标。生产环境设置 `INTELIFAR_REQUIRE_EXTERNAL_AV=true` 后，如果外部扫描器不可用即故障关闭；管理界面明确显示当前是“内置预检”还是“外部恶意软件扫描”，不夸大能力。

上传文件先写入工作空间隔离目录并进入 `security-scan`，安全通过后才允许发送 MinerU。命中恶意规则时进入不可重试的 `blocked` 状态并删除隔离文件；扫描器临时不可用时进入可重试的 `failed` 状态并保留隔离文件。

## 3. 备份方案选择

### 方案 A：直接复制 SQLite/WAL 文件

实现快，但运行时复制可能遗漏 WAL 中尚未 checkpoint 的事务，不能作为可靠备份。

### 方案 B：SQLite 在线备份 + 独立校验（采用）

由 `better-sqlite3` 的在线备份接口生成临时库，再用只读连接执行 `PRAGMA integrity_check`，验证所需表结构后原子改名。每个备份附带仅含非敏感元数据的 manifest（大小、SHA-256、时间、校验结果），默认保留最近 7 份。

恢复操作可能覆盖运行数据，因此本阶段不暴露在线恢复 API。恢复保持为停机、双人复核、先备份当前库、再替换和复核的部署责任。

## 4. 管理员运行台

沿用现有“系统状态”信息架构，增加一个技术化运维台，而不是另造通用仪表盘：

- 安全扫描能力层级、外部扫描是否强制、最近扫描结论；
- 最近备份时间、大小、完整性和 SHA-256 短摘要；
- 当前工作空间审计哈希链校验；
- 最近分析任务及状态，可恢复任务提供明确的“重试”操作；
- 备份创建和校验结果均写入哈希审计链。

viewer/editor 可以继续查看普通系统健康信息，但管理员运行台数据与操作接口只对 owner/admin 开放。

## 5. 安全边界

- 扫描日志和审计事件只记录文件哈希、规则代码和扫描器层级，不保存文档内容。
- 外部扫描程序路径来自部署配置，文件路径由服务端生成，不拼接用户输入。
- 备份 ID 必须符合服务端生成格式，不能作为任意路径读取入口。
- 不提供在线恢复和任意备份下载，降低误操作及数据外泄面。
- 内置预检不是完整反恶意软件引擎；生产健康状态必须如实暴露外部扫描覆盖情况。
