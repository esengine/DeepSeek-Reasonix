# 真实互联网材料批量验收设计

## 目标

用多份公开、可追溯且结构不同的一手材料验证 intelifar 的 MinerU → DeepSeek → 人工复核 → 发布 → 资产图搜索链路，并把一次性人工测试升级为可重复、可审计的批量 E2E。

## 材料选择

| 编号 | 类型 | 一手来源 | 主要挑战 | 预期锚点 |
| --- | --- | --- | --- | --- |
| deepseek-v3 | 英文学术 PDF | arXiv 2412.19437 | 长文、双栏、公式、表格 | MLA、DeepSeekMoE、MTP |
| qwen2.5 | 英文学术 PDF | arXiv 2412.15115 | 长文、多表格、长上下文指标 | 18T tokens、DCA、YARN |
| cn119129722a | 中文专利 HTML | CN119129722A 专利全文 | 权利要求、步骤链、中文实体关系 | RoBERTa、BiLSTM-Attention-CRF、向量库 |

第三方原文件只缓存在 `site/.runtime/internet-corpus/`，不提交仓库。交付物只保存 URL、抓取时间、文件大小、SHA-256、解析统计、脱敏模型结果和截图。

## 基线问题与优化方向

当前 DeepSeek 适配器只截取 MinerU Markdown 的前 60,000 个字符。对真实长文，这会系统性遗漏中后部架构、实验和权利要求；界面却只显示 MinerU 总字符数，用户无法判断实际送入模型的范围。同时，发布证据的 `verified` 只判断引用非空和文档哈希存在，没有验证逐字引用确实出现在模型输入中。

本轮改为“标题感知 + 首尾保留 + 均匀覆盖 + 关键词优先”的确定性分段采样。所有片段保持原文不改写，并输出总字符数、模型输入字符数、总章节数、选中章节数和策略名称。DeepSeek 必须返回原文连续子串；归一化后不在输入中的引用会被剔除并计入校验统计，防止幻觉证据进入发布链。

## 批量 E2E

新增互联网语料清单与批量运行器。运行器只下载清单中固定 HTTPS 主机，限制重定向、响应大小和等待时间，校验扩展名、MIME、魔数、SHA-256 与预期锚点。材料按受控并发提交真实网关，逐一等待 MinerU/DeepSeek 完成、验证引用、发布并查询资产图；单份失败不会覆盖其他材料证据。

成功标准：

- 三份材料均通过安全扫描、MinerU、DeepSeek、发布和证据回溯。
- 每份至少 1 项资产、1 条已验证逐字引用；零未验证引用进入发布。
- 两份长 PDF 使用分段覆盖，且选中章节跨越文档前、中、后部。
- 图资产数量等于各发布资产总和，搜索可命中多文档技术主题。
- API Key 不出现在缓存、报告、截图、日志或 Git 中。

## UI

真实分析结果把“解析完整性”改为“解析与分析范围”，明确区分 MinerU 解析总量和 DeepSeek 实际覆盖范围。长文采用分段覆盖时显示章节数与提示，不再让字符总量被误解为全文已直接送入模型。

## 边界

该验收证明公开技术材料在当前供应商链路上的兼容性，不代表所有扫描件、手写材料或超大企业档案都能达到相同效果。语料内容属于第三方，报告只保留必要统计和短摘要，不再分发全文。
