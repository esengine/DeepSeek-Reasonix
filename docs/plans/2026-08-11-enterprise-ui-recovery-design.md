# intelifar 企业 UI 真实链路修复设计

## 背景

当前 4388 端口的本地真实 UI 由 `real-analysis-server.mjs` 直接启动。未配置登录密码时，启动入口没有传入数据库路径，因此服务退化为原子 JSON：文档分析与发布仍可工作，但成员、审计链、备份、Wiki 版本和受限 Agent 都不可用。前端又把静态演示指标与真实资产混在一起，并在证据 ID 不可解析时直接打开旧的证据抽屉，形成误导和上下文泄漏风险。

## 目标

- 本地售前/小微版本默认使用持久化 SQLite，生产模式仍强制账号密码。
- 把旧的原子 JSON 发布记录幂等迁移到 SQLite，不丢失已经分析并发布的资产。
- 受控本地工作空间拥有真实 owner 成员、哈希审计链、备份和受限 Agent。
- UI 的资产、任务、成员、审计和运行状态来自当前工作空间真实接口；静态样本明确标注为演示。
- 证据抽屉只展示当前点击对象对应的证据。缺失或越权时关闭旧上下文并明确报错。
- 所有新接口继续执行同源校验、角色校验、工作空间隔离、长度/枚举校验和安全输出。

## 架构决定

### 1. 两种明确运行模式

- `local-persistent`：默认开发/售前模式。只监听回环地址，使用 SQLite 与固定本地 owner 身份；没有登录入口，但所有业务写操作仍记录真实审计事件。
- `local-session`：生产/小微正式模式。使用 SQLite、密码会话、RBAC 和安全 Cookie；生产启动继续要求引导密码。
- 仅测试可显式不传数据库而使用原子 JSON。命令行入口不再隐式进入这种模式。

### 2. 兼容迁移

发布注册表在绑定 `platformStore` 后检查旧 `registry.json`。如果当前工作空间没有同 `sourceJobId` 的记录，则使用事务存入 SQLite，同时生成初始 Wiki 版本和资产图投影。重复启动不会重复导入。

### 3. 审计与读模型

平台存储增加只读的工作空间审计列表方法。网关提供 `/api/audit` 与 `/api/dashboard`：返回当前角色可见、当前工作空间范围的数据及哈希链校验结果。前端以这些接口更新 KPI 和审计列表；无法连接服务时才保留明确标记的静态演示。

### 4. 证据上下文隔离

通用证据按钮必须提供可解析的证据 ID；否则不打开抽屉。脱敏样本使用独立、固定且明确标记为演示的证据对象，点击后先覆盖抽屉全部字段，再打开抽屉，并通过受限审计接口记录访问。任何失败都会清空活动证据，避免沿用上一文档内容。

### 5. 图谱真实性

资产图只生成可解析到两个当前工作空间资产的关系，不凭关键词臆造关系。UI 在零关系时显示“尚未建立资产间关系”及创建/复核提示，而不是把 Wiki 中的概念关系冒充资产关系。迁移会重新执行图投影，已有可解析关系会自动出现。

## 风险与处置

- 旧注册表损坏：迁移失败时启动失败并给出安全错误，不删除源文件。
- 本地 owner 无密码：其密码哈希是不可认证哨兵值，且仅在 `authRequired=false` 时作为回环会话身份使用。
- 审计导出：只导出服务端返回的当前工作空间事件；CSV 做公式注入防护。
- 演示证据：显式携带 `sourceMode=demo`，文案不宣称是企业真实文档。
