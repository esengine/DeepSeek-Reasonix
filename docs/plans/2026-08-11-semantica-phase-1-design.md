# Semantica 第一阶段设计：只读语义资产体检

## 目标

给空间管理员提供一次主动触发的只读检查：在其本来可见的已发布资产中发现疑似重复项、同名资产的责任信息冲突，并生成可核对的来源链摘要。检查不得改变正式资产、Wiki、关系或审计真相。

## 用户体验

系统状态页的管理员运维台新增“语义资产体检”。管理员先看到“未启用 / 可用 / 暂不可用”，可用时点击“运行只读检查”。结果使用三种业务语言呈现：

1. 疑似重复：显示两项资产、相似度与判断原因，提示前往资产库人工复核；
2. 信息冲突：显示冲突字段、不同值和来源资产，绝不自动选定正确值；
3. 来源链：显示检查覆盖的资产数和依据数，证明建议基于哪些已发布记录。

## 数据流

1. 管理员请求同源 `/api/semantic/enrich`；
2. 网关验证会话和管理员角色；
3. `publicationRegistry.listAssets(workspaceId, { role })` 先执行空间与密级过滤；
4. Node 适配器裁剪为最多 100 项资产，每项只保留标识、标题、类型、摘要、责任方、密级、标签、来源文档名、校验码和最多 20 条依据定位；
5. 子进程运行锁定版本的 Semantica 去重、冲突和来源链模块；
6. Node 再次校验返回标识只能引用输入资产，向 UI 返回只读结果。

## 安全与可靠性

- 默认关闭；仅 `INTELIFAR_SEMANTICA_ENABLED=true` 时尝试启动；
- `spawn` 使用固定可执行文件和固定桥接脚本，`shell: false`；
- 子进程环境不继承 DeepSeek、MinerU 或其他凭据；
- 输入 1 MB、输出 512 KB、单次 15 秒、100 项资产上限；
- 版本必须为 `0.6.0`，否则拒绝运行；
- 不向 Semantica 发送证据全文或原始上传文档；
- 异常信息脱敏，主业务健康状态保持独立；
- 第一阶段结果不持久化，不提供“自动合并”或“自动纠正”。

## 成功标准

- 适配器的关闭、可用、超时、版本不符、输入裁剪和输出校验均有自动化测试；
- 管理员 API 可用，编辑者与只读成员被拒绝；
- 使用本机官方 Semantica v0.6.0 对真实已发布资产完成一次只读检查；
- Semantica 不可用时，4388 的分析、资产、Wiki、搜索和系统页仍可用；
- 真实 UI 中能看懂状态、运行检查并查看建议，不要求用户理解知识工程术语。
