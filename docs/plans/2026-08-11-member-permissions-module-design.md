# 成员与权限独立模块设计

## 背景与目标

当前成员管理位于“系统状态 → 小微版安全运维台”底部。对第一次使用产品的空间所有者而言，邀请成员、理解角色和处理离职账号是日常治理工作，不应与备份、文件检查和任务恢复混在一起。

本次将成员管理拆分为治理与安全下的独立“成员与权限”模块，使管理员可以快速回答四个业务问题：谁能进入空间、每个人能做什么、哪些邀请仍有效、账号变更会造成什么影响。

## 设计边界

- 仅空间所有者和空间管理员看到并访问完整模块。
- 知识编辑者和只读成员通过侧栏的“我的权限”查看自身能力，不看到成员名单。
- 外部合作方继续使用生命周期模块中的安全分享，不加入空间成员列表。
- 小微企业版不引入部门树、复杂用户组、SCIM、审批流或企业目录同步。
- 所有权限变更复用现有管理员 API、审计记录、所有者保护和会话撤销机制。

## 信息架构

“治理与安全”增加“成员与权限”入口，位于“审计日志”和“系统状态”之间。独立页面包含：

1. 成员概览：有效成员、管理员、待处理邀请、已停用账号。
2. 安全提醒：当只有一位有效管理员时，提示增加第二位管理员，避免单点锁死。
3. 成员列表：姓名、邮箱、角色、状态、最近登录、角色选择与停用/启用操作。
4. 搜索与筛选：按姓名/邮箱搜索，按角色和账号状态筛选。
5. 待处理邀请：展示全部有效邀请及到期时间，可立即撤销。
6. 角色说明：用业务语言解释管理员、编辑者、只读成员的能力边界。
7. 外部协作说明：引导管理员使用“安全分享”，避免误把客户或供应商加入内部空间。

系统状态页不再承载完整成员操作，仅保留一个“成员安全”摘要卡，展示有效成员、管理员冗余和待处理邀请，并跳转到独立模块。

## 关键交互

### 邀请成员

邀请弹窗明确说明当前版本生成一次性邀请链接，不会自动发送邮件。管理员选择角色时即时看到业务权限说明；提交按钮使用“生成邀请链接”。链接只显示一次，管理员需通过可信渠道发送。

### 角色变更

选择新角色后不立即写入。确认弹窗展示成员、新旧角色以及新角色能做和不能做的事。确认后调用现有 PATCH 接口；取消则恢复原选择。

### 停用与启用

停用前说明“所有会话立即失效，历史内容与署名保留”；启用前说明“恢复登录能力，但不会自动创建新会话”。空间所有者和当前账号仍不可被操作。

### 我的权限

所有登录用户均可从侧栏打开“我的权限”，查看角色名称、可执行操作和限制。普通成员不需要理解 RBAC、ABAC 等技术概念。

## 数据与可靠性

成员接口在现有成员字段上增加 `lastLoginAt`，通过会话表中每位用户最近一次 `created_at` 聚合得到，不新增敏感追踪数据。成员查询仍按工作空间隔离。角色或状态修改继续由服务端校验，前端确认只是降低误操作，不作为安全边界。

## 验收标准

- 所有者/管理员可看到并进入“成员与权限”；编辑者/只读成员看不到入口，直接访问时被带回指挥台。
- 成员列表支持搜索与角色/状态筛选，概览数字与真实 API 返回一致。
- 角色变更、停用、启用均需确认且结果由 API 返回决定。
- 邀请弹窗无晦涩英文，明确“不自动发邮件”和“一次性链接”。
- 系统状态页仅显示成员摘要和跳转，不再混入完整成员管理。
- 手机端可完成查看、筛选、邀请和确认操作。
- 单元测试、契约测试、构建和角色化 E2E 全部通过，并保存真实 UI 截图。
