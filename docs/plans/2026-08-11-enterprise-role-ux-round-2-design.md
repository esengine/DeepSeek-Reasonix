# 企业角色体验第二轮优化设计

## 背景

真实企业语料验收已经证明核心链路可用，但当前持久化工作空间仍混有演示计数、静态治理事件和供应商术语；真实 DeepSeek 对两个内置任务模板偶发返回不符合受控计划契约的 JSON，导致用户只看到“安全停止”；审计页对失败事件仍显示“成功”，分析页的原文引用也不能直接回到正式证据。

## 目标

本轮以“真实性与韧性优先”为原则：不扩张 Agent 权限，不引入写操作自动化，先让企业用户看到的数据都来自当前工作空间，让内置任务在模型计划格式漂移时仍能安全完成，让失败、风险与证据路径可理解、可追溯。

## 方案

### 1. 受控 Agent 的确定性兜底

- DeepSeek 仍负责首次计划和一次格式修复。
- 两次计划均未通过服务端契约时，仅对已登记的内置模板生成确定性只读计划。
- 兜底计划只使用现有领域工具；优先使用用户明确选择的资产，否则执行授权资产搜索；不发布、不保存、不修改权限或关系。
- 自由输入任务仍保持失败关闭，避免把未知意图错误映射到模板能力。
- 任务事件记录兜底原因，UI 为失败/中断任务提供“调整后重试”，只回填任务内容，不自动再次调用模型。

### 2. 持久化模式只展示真实数据

- 导航文档数、风险数来自 Dashboard API，不再硬编码 17/23。
- 分析阶段名称改为业务语言，并由当前真实任务的页数、字符数、资产数、证据数和风险数驱动。
- 生命周期页在持久化模式隐藏演示团队、客户和历史事件，改为当前工作空间资产、分享、角色能力及真实审计事件概览。
- 供应商、哈希、令牌等诊断信息保留在需要时可查看的位置，主流程使用“文档读取、知识提取、原文依据”等用户语言。

### 3. 审计语义一致

- 补全 Agent、文件安全检查、关系治理等事件中文名称与摘要。
- 失败、拦截、取消、待复核分别展示对应状态，不再统一显示“成功”。
- 审计页 KPI 直接根据本次日志响应计算，因此后台 Agent 新事件在刷新后与列表一致。
- Agent 任务进入终态时通知主应用刷新 Dashboard、审计和运维概览。

### 4. 原文依据闭环

- 分析结果中的引用改为可聚焦、可点击的证据卡片。
- 发布后用正式证据的原文、章节和资产标题匹配分析引用，点击后复用现有证据抽屉。
- 发布前或无法匹配时明确提示“发布后可打开正式证据”，不伪造证据编号。

## 安全边界

确定性兜底不会绕过 `validateAgentPlan`，也不会新增工具。每一步仍由当前账号、工作空间与角色重新鉴权；模型只收到有界工具回执；自由输入计划格式失败仍安全停止。UI 仅回填重试内容，用户必须主动提交。

## 验收标准

- 两次无效 DeepSeek 计划下，内置盘点和尽调模板能生成合法只读计划；自由输入仍失败关闭。
- 持久化工作空间中不出现 17/23、推理架构组、华辰智算研究院等演示内容。
- 真实分析阶段数字与任务结果一致。
- `agent.task_failed` 显示中文事件名与“失败”，Agent 终态后审计 KPI 与日志数一致。
- 已发布分析引用可打开正式证据抽屉。
- Node 单元/契约测试、前端构建、Playwright 关键 E2E 和真实语料 UI 验收通过。
