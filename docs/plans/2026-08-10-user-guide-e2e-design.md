# intelifar 用户手册与全模块验收设计

## 目标与读者

交付一份可直接用于售前演示、客户试用、内部培训和管理员交接的中文 Markdown 手册。读者包括空间所有者、管理员、知识编辑者、只读成员、外部受邀阅览者和部署运维人员。手册必须明确区分真实服务能力、离线演示内容和仍由生产部署方承担的责任，不能把静态示例描述为客户数据。

## 方案选择

考虑了三种结构：单一线性操作手册最容易阅读，但角色和模块交叉时重复严重；拆成管理员、编辑者、访客等多份手册便于分发，但难以维护统一口径；最终采用“快速开始 + 角色矩阵 + 端到端链路 + 模块字典 + 场景教程 + 运维排障 + E2E 证据”的分层结构。它既能让首次用户在五分钟内完成登录和浏览，也能让管理员按模块查找权限、安全和故障处理细节。

## 信息架构

手册先说明产品边界和四级角色，再用 Mermaid 描述“文档接入 → 安全扫描 → MinerU → DeepSeek → 人工复核 → 发布资产 → Wiki 版本 → 脱敏分享 → 审计”的主链。每个主模块使用固定模板：功能定位、典型场景、适用角色、前置条件、操作步骤、结果判断、异常处理和安全提示。协作链单列成员邀请、账号激活、角色调整、禁用和双通道分享；运维链单列扫描、任务恢复、备份校验和部署责任。

## 测试设计

现有 E2E 已分别验证离线功能、真实供应商、认证 Wiki、安全运维和协作分享。本阶段新增“全模块巡检”测试，以真实 SMB 会话依次打开指挥台、文档中心、智能分析、IP 资产库、IP Wiki、脱敏与溯源、生命周期、审计日志、系统状态，断言每个视图唯一可见且关键操作存在；补充全局检索、资产详情、证据抽屉、审计筛选、主题切换、管理员成员入口和编辑者权限边界。文档契约测试检查角色、全部模块、主链、安全边界、E2E 命令和截图引用，避免 UI 演进后手册悄然缺页。

## 完成标准

- 完整手册可从中英文 README 和交付说明进入。
- 九个内部模块、两个公开页面和管理员运维能力均有功能与场景说明。
- 至少一条端到端业务教程、管理员教程和外部分享教程可逐步执行。
- 现有五套 E2E 与新增全模块巡检全部通过。
- 真实 MinerU → DeepSeek 验收、依赖审计、凭据扫描和 Markdown 链接检查通过。
