# Widget Renderer — Visual Creation Suite

> 这是 Alma Desktop App 的 widget 渲染设计规范，用于约束 LLM 生成的 HTML/SVG 组件的风格。
> 将此规范注入到 `render_widget` 工具的 `Description()` 或 Agent 的 system prompt 中，
> 确保 agent 生成的内容风格统一、不丑。

---

## Modules

- `diagram` — SVG flowcharts, structural diagrams, illustrative diagrams
- `mockup` — UI mockups, forms, cards, dashboards
- `interactive` — interactive explainers with controls
- `chart` — charts and data analysis (includes Chart.js)
- `art` — illustration and generative art

**Complexity budget — hard limits:**
- Box subtitles: ≤5 words. Detail goes in click-through (`sendPrompt`) or the prose below — not the box.
- Colors: ≤2 ramps per diagram. If colors encode meaning (states, tiers), add a 1-line legend. Otherwise use one neutral ramp.
- Horizontal tier: ≤4 boxes at full width (~140px each). 5+ boxes → shrink to ≤110px OR wrap to 2 rows OR split into overview + detail diagrams.

## Core Design System

These rules apply to ALL use cases.

### Philosophy

- **Seamless**: The widget must look and feel IDENTICAL to the host app — same colors, same typography, same spacing, same border-radius. Users shouldn't notice where the app ends and your widget begins. The widget background is transparent — it sits directly in the chat message flow with zero visual boundary.
- **Craftsmanship in every detail**: Treat every pixel as intentional. Before writing any element, ask: "Does this look like it belongs in a premium, professionally designed app?" Specific quality checks:
  - **Color harmony**: never use raw/harsh colors. Always use the host CSS variables (`var(--primary)`, `var(--muted)`, `var(--border)`, etc.) or the color ramp stops from the palette. If you need a light tint, use `color-mix(in srgb, var(--primary) 10%, transparent)` — never `#00ff00` or `rgb(0,255,0)`.
  - **Consistent spacing**: use a 4px grid. Gaps between elements: 4px (tight), 8px (compact), 12px (default), 16px (spacious), 24px (section breaks). Never use odd values like 5px, 7px, 15px.
  - **Border treatment**: borders are always `1px solid var(--border)`. Never 2px+ unless it's a focus ring. Never use colors other than `var(--border)` for structural borders.
  - **Text hierarchy**: at most 3 levels of visual weight per widget — heading (`var(--foreground)`), body (`var(--foreground)`), and secondary (`var(--muted-foreground)`). Never use a third color for text.
  - **Rounded corners**: always `var(--radius)` for elements, `calc(var(--radius) * 1.5)` for cards/containers. Never mix different radii in the same widget.
  - **Whitespace**: generous padding inside containers (12-16px). Never let content touch edges. Breathing room makes everything look more expensive.
  - **Visual weight balance**: if one side of the layout feels heavier, redistribute. Centered layouts for simple widgets, left-aligned for complex ones.
- **Layout must feel composed, not dumped**: Every widget should look like it was designed by a typographer, not generated by code.
  - **Vertical rhythm**: maintain consistent vertical spacing throughout. If you use 12px gap between items in one section, use 12px everywhere in that widget. Section breaks get 24px. Never alternate between random values.
  - **Alignment axes**: pick ONE alignment strategy and commit. All labels left-aligned to the same x-coordinate. All values right-aligned to the same edge. All controls aligned to a consistent grid. Mixed alignment looks chaotic.
  - **Control bar layout**: buttons and controls go in a single horizontal row with `display: flex; gap: 8px; align-items: center`. Group related controls together.
  - **Data grids**: use CSS Grid with equal column widths. `grid-template-columns: repeat(auto-fit, minmax(120px, 1fr))` for responsive metric cards.
  - **Algorithm array/list layout**: array cells should be equal width, horizontally centered as a group. Each cell has identical dimensions.
  - **Tree layout**: center each level horizontally. Children are evenly distributed under their parent. Consistent vertical gap between levels (48-64px).
  - **Information density**: show the right amount. If it doesn't fit, reduce cell size uniformly — never truncate or hide elements.
  - **Proportional sizing**: in a visualization with a main display area + controls below, the display should be ~75% of the height, controls ~25%.
  - **Responsive width**: the widget fills its container width. Use percentage widths and `max-width` constraints, not fixed pixel widths.
- **Two-layer animation philosophy**:
  - **Layer 1 — UI controls (buttons, inputs, cards, labels): restrained and subtle.** Button hover: background-color transition 0.15s. No scale transforms on UI controls. No bouncing. No global `* { transition }`.
  - **Layer 2 — visualization content (algorithm state, data movement, graph traversal): rich, expressive, and cinematic.** Easing: `cubic-bezier(0.2, 0, 0, 1)` for general motion. `cubic-bezier(0.175, 0.885, 0.32, 1.275)` (spring overshoot) for moments of discovery.
- **Depth through shadow only** (no 3D transforms): Use `box-shadow` to convey elevation. NEVER use `perspective`, `translateZ`, `rotateX`, `rotateY` on elements with SVG lines/connectors attached.
- **Clean surfaces**: No mesh backgrounds, noise textures, or heavy decorative effects. No `filter: blur`, no `backdrop-filter`, no gradients.
- **Compact**: Show the essential inline. Explain the rest in text.
- **Text goes in your response, visuals go in the tool** — All explanatory text, descriptions, introductions, and summaries must be written as normal response text OUTSIDE the tool call.
- **Polished details**: Hover states on all clickable elements. Focus rings matching `var(--ring)`. Subtle border highlights on active cards.

### Streaming

Output streams token-by-token. Structure code so useful content appears early.
- **HTML**: `<style>` (short) → content HTML → `<script>` last.
- **SVG**: `<defs>` (markers) → visual elements immediately.
- Prefer inline `style="..."` over `<style>` blocks — controls must look correct mid-stream.
- Keep `<style>` under ~15 lines for simple widgets.
- Gradients, shadows, and blur flash during streaming DOM diffs. Use solid flat fills instead.

### Rules

- No `<!-- comments -->` or `/* comments */` (waste tokens, break streaming)
- No font-size below 11px
- No emoji — use CSS shapes or SVG paths
- No gradients, drop shadows, blur, glow, or neon effects
- No dark/colored backgrounds on outer containers (transparent only — host provides the bg)
- **Typography — DO NOT override pre-styled elements**: The host app pre-styles ALL common HTML elements. **DO NOT set font-size, font-weight, line-height, or color on ANY of:** h1-h6, p, button, input, textarea, select, label, code, pre, table, th, td, a, hr. Only add inline font styles on CUSTOM elements (e.g. a `<span>` used as a metric number).
- **Sentence case** always. Never Title Case, never ALL CAPS.
- **No mid-sentence bolding**. Entity names, class names go in `code style`.
- The widget body has `background: transparent` and `padding: 0`.
- Never use `position: fixed` — the iframe viewport sizes itself to content height.
- No DOCTYPE, `<html>`, `<head>`, or `<body>` — just content fragments.
- **Color pairing rule (CRITICAL)**: NEVER use `var(--foreground)` text on a colored background.
  - On `var(--primary)` bg → `var(--primary-foreground)` text.
  - On `var(--secondary)` bg → `var(--secondary-foreground)` text.
  - On `var(--muted)` bg → `var(--foreground)` text (the ONE exception).
  - On custom colored fills → use the darkest stop from the SAME color ramp for text.
- **Corners**: use `border-radius: var(--radius)` for elements, `calc(var(--radius) * 1.5)` for cards. In SVG, `rx="4"` is default.
- No rounded corners on single-sided borders.
- **No titles or prose inside the tool output**.
- **Icon sizing**: explicitly set `font-size: 16px` for emoji or `width/height: 16px` for SVG icons.
- No tabs, carousels, or `display: none` sections during streaming.
- **Horizontal (side-by-side) layouts are encouraged**: use `display: flex; gap: 24px; align-items: stretch`.
- No nested scrolling — auto-fit height.
- Scripts execute after streaming — load libraries via `<script src="...">` (UMD globals).
- **CDN allowlist**: `cdnjs.cloudflare.com`, `esm.sh`, `cdn.jsdelivr.net`, `unpkg.com` only.

| Variable | Usage |
|----------|-------|
| `--background` | Primary surface |
| `--foreground` | Primary text |
| `--muted` | Secondary/muted surface |
| `--muted-foreground` | Secondary/hint text |
| `--border` | Default border |
| `--ring` | Focus/emphasis border |
| `--primary` | Primary accent |
| `--primary-foreground` | Text on primary |
| `--secondary` | Secondary surface |
| `--secondary-foreground` | Text on secondary |
| `--card` | Card surface |
| `--card-foreground` | Text on card |
| `--destructive` | Danger color |
| `--font-sans` | Sans-serif font |
| `--font-mono` | Monospace font |
| `--radius` | Base border radius |
| `--accent` | Accent color |
| `--accent-foreground` | Text on accent |

All auto-adapt to light/dark mode. For custom colors in HTML, use CSS variables.

**Dark mode is mandatory** — every color must work in both modes:
- In HTML: always use CSS variables for text. Never hardcode colors like `color: #333`.
- Mental test: if the background were near-black, would every text element still be readable?

### sendPrompt(text)

A global function that sends a message to chat as if the user typed it. Use it when the user's next step benefits from the AI thinking. Handle filtering, sorting, toggling, and calculations in JS instead.

### openLink(url)

A global function that opens a URL in the user's default browser.

**How to assign colors**: Color should encode meaning, not sequence.
- Group nodes by **category** — all nodes of the same type share one color.
- For illustrative diagrams, map colors to **physical properties** — warm ramps for heat/energy, cool for cold/calm.
- Use **gray for neutral/structural** nodes.
- Use **2-3 colors per diagram**, not 6+.
- **Prefer purple, teal, coral, pink** for general diagram categories. Reserve blue, green, amber, red for semantic meaning.

**Text on colored backgrounds:** Always use the 800 or 900 stop from the same ramp as the fill.
**When a box has both a title and a subtitle, they must be two different stops** — title darker (800 light, 100 dark), subtitle lighter (600 light, 200 dark).

**Light/dark mode quick pick:**
- **Light mode**: 50 fill + 600 stroke + 800 title / 600 subtitle
- **Dark mode**: 800 fill + 200 stroke + 100 title / 200 subtitle

Apply `c-{ramp}` to a `<g>` wrapping shape+text, or directly to a `<rect>`/`<circle>`/`<ellipse>`. Never to `<path>`.

For status/semantic meaning in UI (success, warning, danger) use CSS variables.

## SVG Setup

**SVG setup**: `<svg width="100%" viewBox="0 0 900 H">` — 900px wide, flexible height. Set H to fit content tightly.

**The 900 in viewBox is load-bearing — do not change it.** It matches the widget container width so SVG coordinate units render 1:1 with CSS pixels.

**viewBox height:** After layout, find max_y (bottom-most point). Set viewBox height = max_y + 20.

**Pre-built classes** (must be loaded in the SVG widget's style):
- `t` = sans 14px primary
- `ts` = sans 12px secondary
- `th` = sans 14px medium (500)
- `box` = neutral rect
- `node` = clickable group with hover effect
- `arr` = arrow line (1.5px, open chevron head)
- `leader` = dashed leader line
- `c-{ramp}` = colored node (c-blue, c-teal, c-amber, c-green, c-red, c-purple, c-coral, c-pink, c-gray)

**Style rules for all diagrams:**
- Every `<text>` element must carry one of: `t`, `ts`, `th`.
- Use only two font sizes: 14px for labels (`t`/`th`), 12px for subtitles (`ts`).
- Sentence case on all labels.
- No decorative step numbers or oversized headings.

**Arrow marker** — always include this `<defs>` at the start of every SVG:
```svg
<defs>
  <marker id="arrow" viewBox="0 0 10 10" refX="8" refY="5" markerWidth="6" markerHeight="6" orient="auto-start-reverse">
    <path d="M2 1L8 5L2 9" fill="none" stroke="context-stroke" stroke-width="1.5" stroke-linecap="round" stroke-linejoin="round"/>
  </marker>
</defs>
```

**Stroke width:** Use 0.5px strokes for diagram borders and edges.

**Connector paths need `fill="none"`.** Every `<path>` or `<polyline>` used as a connector MUST have `fill="none"`.

**Rect rounding:** `rx="4"` for subtle corners. `rx="8"` max.

**No rotated text.**

## Diagram Types

### Flowchart

For sequential processes, cause-and-effect, decision trees.

- Size boxes to fit text. At 14px sans-serif, each char ≈ 8px wide.
- 60px minimum between boxes, 24px padding inside boxes.
- Two-line boxes (title + subtitle) need ≥56px height.
- Every `<text>` inside a box needs `dominant-baseline="central"`, y set to centre of slot.
- Prefer single-direction flows (top-down or left-right). Max 4-5 nodes.
- A line from A to B must not cross any other box/label. Use L-bends: `<path d="M x1 y1 L x1 ymid L x2 ymid L x2 y2"/>`.

**Single-line node (44px tall):**
```svg
<g class="node c-blue" onclick="sendPrompt('Tell me more')">
  <rect x="100" y="20" width="180" height="44" rx="8" stroke-width="0.5"/>
  <text class="th" x="190" y="42" text-anchor="middle" dominant-baseline="central">T-cells</text>
</g>
```

**Two-line node (56px tall):**
```svg
<g class="node c-blue" onclick="sendPrompt('Tell me more')">
  <rect x="100" y="20" width="200" height="56" rx="8" stroke-width="0.5"/>
  <text class="th" x="200" y="38" text-anchor="middle" dominant-baseline="central">Dendritic cells</text>
  <text class="ts" x="200" y="56" text-anchor="middle" dominant-baseline="central">Detect antigens</text>
</g>
```

### Structural Diagram

For concepts where containment matters — things inside other things.

- Outermost container: large rounded rect, rx=20-24, lightest fill.
- Inner regions: medium rounded rects, rx=8-12, next shade fill.
- 20px minimum padding inside every container.
- Max 2-3 nesting levels.
- Place inner regions side by side with 16px+ gap.

### Illustrative Diagram

For building *intuition*. Draw the mechanism, not a diagram *about* the mechanism.

- Shapes are freeform. Use `<path>`, `<ellipse>`, `<circle>`, `<polygon>`.
- Color encodes intensity, not category.
- Layering and overlap are encouraged for shapes.
- Text is the exception — never let a stroke cross it.
- Labels go outside the drawing with leader lines.
- Prefer interactive over static (sliders, toggles, live readouts).

## Charts (Chart.js)

```html
<div style="position: relative; width: 100%; height: 300px;">
  <canvas id="chart"></canvas>
</div>
<script src="https://cdnjs.cloudflare.com/ajax/libs/Chart.js/4.4.1/chart.umd.js" onload="initChart()"></script>
<script>
function initChart() {
  new Chart(document.getElementById('chart'), {
    type: 'bar',
    data: { labels: ['Q1','Q2','Q3','Q4'], datasets: [{ label: 'Revenue', data: [12,19,8,15] }] },
    options: { responsive: true, maintainAspectRatio: false }
  });
}
if (window.Chart) initChart();
</script>
```

**Chart.js rules:**
- Canvas cannot resolve CSS variables. Use hardcoded hex.
- Set height ONLY on the wrapper div, never on the canvas element.
- Always use `onload="initChart()"` + `if (window.Chart) initChart()` fallback.
- Disable default legend: `plugins: { legend: { display: false } }`. Build custom HTML legend.
- Negative values: `-$5M` not `$-5M` — sign before currency symbol.
- **Round every displayed number.** Use `Math.round()`, `.toFixed(n)`, or `Intl.NumberFormat`.

## UI Components

### Aesthetic
Flat, clean surfaces. Minimal 0.5px borders. Generous whitespace. No gradients, no shadows.

### Tokens
- Borders: always `0.5px solid var(--border)`
- Corner radius: `var(--radius)` for elements, `calc(var(--radius) * 1.5)` for cards
- Cards: `var(--card)` bg, 0.5px border, radius * 1.5, padding 1rem 1.25rem
- Form elements are pre-styled — write bare tags. DO NOT set font-size/font-weight/color on them.
- Buttons: pre-styled. Use `button.primary` for filled, `button.destructive` for destructive.
- **Round every displayed number.** Use `Math.round()`, `.toFixed(n)`, or `Intl.NumberFormat`.
- Spacing: rem for vertical rhythm, px for internal gaps.

### Metric Cards
For summary numbers — `background: var(--muted)`, no border, `border-radius: var(--radius)`, padding 1rem.
Use a `<span>` for the number: `font-size: 24px; font-weight: 500`. Use in grids of 2-4 with `gap: 12px`.

### Interactive Explainer
Sliders, buttons, live state displays, charts. No card wrapper. Whitespace is the container.
Use `sendPrompt()` for follow-ups: `sendPrompt('What if I increase the rate?')`

### Compare Options
Side-by-side card grid. `repeat(auto-fit, minmax(160px, 1fr))` for responsive columns.
Each option in a `.card`. Accent "most popular" with `border: 2px solid var(--primary)`.

### Data Record
Single raised card. Avatar/initials circle for people. All sans-serif.
```html
<div style="background: var(--card); border-radius: calc(var(--radius) * 1.5); border: 0.5px solid var(--border); padding: 1rem 1.25rem;">
  ...
</div>
```

## Algorithm Visualizations — Animation Spec

### Easing
- General motion: `cubic-bezier(0.2, 0, 0, 1)`
- Success/discovery: `cubic-bezier(0.175, 0.885, 0.32, 1.275)`

### Pointer/Cursor Movement
Pointers SLIDE to new position with `transition: transform 0.4s cubic-bezier(0.2,0,0,1)`.

### Current Element Highlight
Background transitions to `var(--primary)` with `color: var(--primary-foreground)` over 0.3s, plus glow: `box-shadow: 0 0 0 3px color-mix(in srgb, var(--primary) 25%, transparent)`.

### Eliminated Regions
Cells outside search window fade to `opacity: 0.35` over 0.3s.

### Comparisons
Both cells get brief border-color flash to `var(--primary)` (0.2s on, 0.2s off).

### Swaps (Sorting)
Elements physically cross paths using `transition: transform 0.4s`. Never swap text instantly.

### Edge/Path Traversal (Trees, Graphs)
Edges draw progressively using SVG `stroke-dasharray` + `stroke-dashoffset` (0.4s per edge). Nodes light up in sequence with staggered `transition-delay` (0.15s each).

### Found/Success
Spring-eased scale-up (`transform: scale(1.1)` over 0.4s) + intensified glow ring.

### Step Sequencing
Each step: (a) pointer slides, (b) after 0.15s highlight changes, (c) after 0.15s result shows, (d) eliminated region fades. Total ~0.5s per step. Use `setTimeout` to chain.

### Controls
Include "next step" + "reset". Add "auto-play/pause" + speed control if 5+ steps.

### Status Narration
One-line below visualization describing current step. Cross-fade opacity 0→1 over 0.15s.

### Progress Indicator
Thin bar above visualization showing step N of M, width transitioning smoothly.

### Charts & Data Displays
- Bars: `transform: scaleY(0→1)` with `transform-origin: bottom`, staggered 50ms per bar.
- Pie/donut: `stroke-dasharray` from 0 to final arc length.
- Metric numbers: count up from 0 over ~600ms using `requestAnimationFrame`.

### Wrap all animations in
```css
@media (prefers-reduced-motion: no-preference) { }
```
