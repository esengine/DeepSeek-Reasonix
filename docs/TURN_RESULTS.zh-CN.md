# 本轮结果

[English](TURN_RESULTS.md)

一轮执行产生文件改动或检查记录后，桌面端在回答下方显示**本轮结果**，分别展示已确认的文件净变化与实际检查状态。检查通过仅描述已记录的检查，不是对整个任务完成度的评分。

- **查看差异**：打开该轮结束时保存的差异。同一文件多次修改只计一次，以本轮首次捕获的内容为基线；改回原样不增加行数。用户原有的未提交修改属于基线，不会算作智能体本轮新增的改动。
- **查看检查详情**：展示命令、退出码、过期或中断状态，以及可展开的日志。只有宿主识别为检查且已进入执行的命令，才会显示“验证中…”。
- **当前工作区全部差异**：返回原有工作区视图，查看包括其他轮次和外部修改在内的当前变化。

这些入口仅用于查看，不执行、重跑或安排检查，也不需要新增配置。

## 统计范围与历史

“部分统计”表示无法可靠归属所有修改，或内容超出了捕获及差异处理的大小限制。已确认的数量仍会显示；未知部分不会通过 Git HEAD、工具调用次数或变更回执数量来猜测。

二进制和仅权限变化的文件有独立标识，不虚构行数。无法精确统计的大改动与无法保留的补丁详情会明确标注。移动文件沿用已有捕获机制记录的路径，不额外推断重命名。

历史卡片保留当时的统计。打开旧轮次不会按当前磁盘内容重新计算差异。若 checkpoint 详情已清理，摘要仍保留，并提示详情不可用。旧会话缺少结果元数据时，显示“改动统计不可用”“检查信息不完整”，不会显示成零改动或检查通过。

日志从已有本地会话记录读取，同时校验工具调用 ID 与轮次结束时关联的稳定消息 ID。即使供应商后续复用工具调用 ID，也不会让旧卡片读取新日志。来源有歧义、尚未产生或已清理时明确提示不可用。单次显示上限为 2 MiB；仅保留末尾时会提示截断。

## 实现与兼容性

宿主在既有 `turn_done.receipt` 中增加可选的 `diff` 与检查来源字段，使用既有检查分类和执行策略。差异摘要包含轮次、不可变结果 ID、覆盖范围、文件与增删行数，事件和历史摘要不携带补丁正文。

Checkpoint 在本轮结束、下一轮尚不能开始时保存结果，复用原有非阻塞写入屏障，并校验写入后的指纹。每轮参与处理的内容与保留补丁共限 2 MiB；差异算法的近似计数不作为精确统计展示。结果沿用 checkpoint 的清理策略，补丁元数据纳入磁盘预算。

桌面端复用已有显示记录与持久事件重放。结果卡通过共同的轮次投影放在回答之后，并保留稳定组件 ID。会话、标签页和结果标识隔离延迟返回的差异与日志。模型提示词、工具 schema 和执行权限不变。

## 验证方法

回归测试覆盖多次修改的净变化、无变化、原有脏文件、删除、二进制、权限变化、并发与外部写入、大小限制、重新打开、旧版本读取、中断和失败轮次、检查退出码、日志稳定标识、历史显示重放、重复事件、并行检查，以及切换会话后的迟到响应。

在 `desktop/frontend` 运行 `pnpm dev`，按 Vite 输出的网址打开 `/bench/turn-result.html`。该页面使用真实 Transcript、状态归约器、结果面板和差异组件，执行数据为模拟数据；可切换成功、失败、未检查、过期、中断、执行中、部分统计、旧格式与历史场景，并验证主题、窄面板和数据清理。添加 `?transcriptRenderMode=windowed` 可验证同一结果在窗口化列表中的显示。

此页面截图用于证明界面与交互；真实存储、指纹校验和控制层结束流程由独立后端测试证明。
