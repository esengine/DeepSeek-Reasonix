# Release note format

Use only sections supported by the selected changes:

## Highlights

- State a user-visible change and cite its commit or pull request.

## Fixes

- State the corrected behavior and its trigger; cite the change.

## Upgrade notes

- State an action users must take, or omit this section when none is verified.

## Validation

- Name a check and its observed result. If no check result is available, write
  “Validation not verified from the selected evidence.”

Before handing over the draft, check that every factual claim follows from a
selected source. Keep missing context in a short “Needs confirmation” note; do
not silently fill it with plausible release details.
