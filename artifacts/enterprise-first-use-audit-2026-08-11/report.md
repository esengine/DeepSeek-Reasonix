# intelifar 企业岗位首次使用体验报告

日期：2026-08-11  
交付入口：`http://127.0.0.1:4388/`  
真实材料审计环境：同一前端与服务端代码启动的隔离鉴权工作空间；测试完成后已停止，不与交付入口的数据混写  
体验范围：真实 UI、真实会话权限、真实公开材料、真实 MinerU/DeepSeek 既有处理结果、桌面端与 390×844 移动端  
体验角色：空间所有者、知识编辑者、只读成员、外部接收方  

## 1. 结论

产品主链路已经真实可用：文档接入 → MinerU 读取 → DeepSeek 提取 → 原文依据校验 → IP 资产与关系复核 → Wiki 发布/版本化 → 受控 Agent → 安全分享与审计。空间所有者与知识编辑者可以较完整地完成知识沉淀工作，外部接收方也能通过链接与独立访问码查看只读 Wiki。

但从“企业不同岗位第一次接触，且默认无技术背景”的角度，当前综合评分为 **84/100**，暂不建议直接向外部客户开放全角色试点。这里的分数低于此前针对功能完成度的 98+ 分，是因为本轮新增了角色隔离、错误真实性、第一次理解成本和外部交付质量四类更严格标准。

上线前必须先解决两个阻断问题：

1. **只读成员可以查看并导出整个工作空间的审计记录。** 记录中包含其他成员身份、分享接收方、登录/退出、备份和管理员操作，不符合普通阅读岗位的最小权限原则。
2. **只读成员仍可操作“接入文档/新建分析”。** 服务端最终以 403 拒绝，但界面先提示“真实分析任务已启动”，随后显示英文权限错误、2% 假进度和上一任务编号，容易让用户误判数据是否已经外传或任务是否真实创建。

## 4. 完整模块与按钮体验

### 4.1 指挥台

已操作：查看审计、接入新文档、进入安全工作台、查看全部资产、最新资产原文依据、主题切换、通知、全局搜索、新建分析。

有效之处：

- 真实空间中显示 26 个资产、3 份文档、8 个风险提示和 100% 证据覆盖，演示数据不会混入关键指标。
- 四个主要跳转按钮均能进入对应模块，适合管理者快速浏览。

第一次会问：

- “12.4% 上升”与“目标 ≥95%”的统计周期、分母和责任人是什么？
- “风险 8 项”是待处理、已确认还是仅供提醒？
- 为什么通知按钮点击后没有明确内容或空状态？

建议：每个指标增加一句业务解释、统计口径和可执行下一步；没有真实数据的趋势不要保留固定演示百分比。

### 4.2 文档中心与文档接入

已操作：接入文档、真实文件选择、拖放区域、离线演示、名称/分类必填校验、责任部门、密级、敏感识别、搜索、状态筛选、高级筛选、列表视图、刷新、行操作、全选与分页。

有效之处：真实 PDF/HTML 可被文件选择器识别，空表单校验明确，文件名和大小会回显。

主要问题：

- 使用过“离线演示”后再选择真实文件，演示分类“技术白皮书”仍被保留，真实文档可能被静默误分类。
- “高级筛选”提示“字段可由 Schema 扩展”，首次使用者不知道 Schema 是什么、谁来配置。
- 列表/刷新图标缺少选中态或刷新反馈。
- 对话框承诺“生成不可逆涂黑副本”，但当前真实产品只提供风险线索查看，没有可下载的涂黑副本交付，属于能力描述过度。
- 只读成员仍能打开、选文件并提交；服务端虽拒绝，前端却先显示成功和旧任务状态。

建议：切换真实文件时清空演示字段；把“Schema”改成“自定义字段（由管理员配置）”；仅 editor 及以上显示接入入口；把涂黑副本承诺改为当前真实能力，或补齐生成/复核/下载链路。

### 4.3 智能分析

已操作：三份真实任务切换、任务阶段、总体进度、运行日志、原文依据、发布/重新发布、新分析。

有效之处：Qwen2.5 页面如实显示 114,001 字符解析量、60,000 字符分析范围、25 个章节和 19/19 引用；能切换三份历史任务并回到真实结果。

第一次会问：

- 为什么系统“读取了全文”，但只分析其中 60,000 字符？剩余内容是否可能遗漏关键风险？
- “章节平衡抽样”如何决定优先级？能否让法务优先合同条款、研发优先技术参数？
- “发布”到底会让谁看到？发布前是否需要审批？

建议：把抽样策略改为业务语言，展示“已覆盖/未覆盖章节”；允许选择分析目标；发布前显示资产、证据、关系变化预览及审批人。

### 4.4 IP 任务助手

已操作：资产盘点、影响分析、证据核查、资产对比、Wiki 草案、风险缺口、尽调材料七个模板；自由文本；委托、刷新、任务历史、证据/资产跳转、调整重试、取消任务、安全边界。

有效之处：

- 只读成员可以执行只读任务，Wiki 草案模板正确禁用；任务历史只显示本人任务。
- 取消任务后状态正确为“已取消”，不会改动正式知识。
- DeepSeek 不可用时可以降级到确定性只读结果，且不会绕过权限。
- 证据按钮能回到原始材料，Agent 没有成为 coding agent 或任意外网工具。

主要问题：

- “Reasonix 任务语义”“最多 6 步”“最大 12 工具调用”“交付门禁”仍是研发视角词汇。
- 管理员尽调任务显示“需要复核”，同时又显示“确定结论 12 项”，状态自相矛盾。
- 只读成员证据核查结论写“共 22 项”，待核实部分又称“当前仅返回 20 条”；结果内部口径冲突。
- 结果大量列出 `IP-REAL-*`、`EV-*` 内部编号，不适合作为对客户或管理层的交付物。
- 任务历史在桌面端出现横向滚动和文本裁切。

建议：把工程指标收进“运行详情”；“确定结论”改为“有依据条目”，明确已确认/待复核数量；交付前执行数量一致性校验；默认显示业务名称，内部编号放到可复制的详情中；提供“管理层摘要/法务核查表/客户答复”三种稳定输出格式。

### 4.5 IP 资产库与全景图

已操作：神经网络全景图、列表模式、放大、缩小、重置、节点搜索、密级筛选、节点详情、一跳关系、证据、Wiki、关系详情、关系证据、确认、拒绝、标签筛选、导入资产、新建资产。

有效之处：26 个真实节点可缩放、拖动和搜索；查看者只收到已确认关系；编辑者可在证据支持下确认或拒绝建议关系。

主要问题：

- 初始 14 条关系全部是待复核，视觉很“高级”，但人工复核前不能可靠用于影响分析。
- 图中“65% 覆盖”缺少分母说明。
- “查看一跳关系”会关闭当前详情，用户需要再次选中节点才能继续看资产详情。
- “导入资产”“新建资产”点击后没有对话框、提示或动作，是明显的空按钮。
- “标签筛选”只提示用户在搜索框输入，没有真正筛选器。

建议：增加关系复核收件箱、按置信度/影响范围排序；解释覆盖率；保留节点详情并高亮一跳；未实现按钮移除或标注“即将支持”；搜索与标签筛选分开。

### 4.6 IP Wiki

已操作：目录跳转、搜索、回车定位、专注阅读、原文依据、关联知识、编辑、保存新版本、历史版本、分享。

有效之处：搜索“模型”能匹配三个章节；证据、资产、版本互相可达；本轮完成 V1.0 → V1.1 → V1.2 的追加式版本验证，并将测试内容恢复到原始文案，历史仍可追溯。

主要问题：

- 编辑器一次展示很长的摘要/机制正文，没有差异对比、预览或审批。
- 内容未变化时“保存新版本”仍可用，容易产生无意义版本。
- 指标下仍显示“来自 DeepSeek 结构化结果”，对业务读者意义有限。
- 只读成员的编辑/分享按钮只显示灰态，缺少常驻解释。

建议：保存前展示变更差异和影响范围；无变化时禁用保存；支持“提交复核”而非编辑者直接发布；把模型来源改为“来自《文档名》并已核验”，模型细节收进证据详情。

### 4.7 脱敏与溯源

已操作：风险卡片、来源原文、原文依据、打开智能分析、筛选与当前三份材料的风险列表。

有效之处：8 个提示能回到来源，无法匹配的提示明确标记“仍需补充依据”，没有伪造引用。

主要问题：模块名称像“可执行工作台”，实际是只读风险清单；没有负责人、状态、复核结论、标记已解决、批量处理、导出或涂黑副本。

建议：短期改名为“敏感信息与风险线索”；中期增加指派、确认/误报、处理说明、状态、批量导出；只有真正提供涂黑预览和下载后再称“脱敏工作台”。

### 4.8 生命周期与安全分享

已操作：角色能力、治理事件、创建分享、邮箱/有效期校验、一次性链接与访问码、错误访问码、正确访问、撤销、撤销后新窗口重试。

有效之处：链接和访问码分离，公开页只返回只读 Wiki；撤销后新的访问请求会失败；所有动作进入审计。

主要问题：

- 全景图仍有 12 条待复核关系时，生命周期“待确权/复核”显示 0，因为该指标只统计资产字段，名称会误导管理者。
- 治理事件显示原始字段名、UUID、ISO 时间，不适合业务人员。
- 公开页出现 “SECURE WIKI ROOM”“REDACTED KNOWLEDGE EDITION”等英文，没有联系人、问题反馈或下载说明。
- 撤销提示称“原链接与访问码已立即失效”，但已经加载到浏览器的页面仍可继续阅读；已展示或复制的内容无法召回。

建议：将资产和关系待复核分开统计；治理事件翻译成“谁、何时、对什么做了什么”；公开页全中文并增加企业联系人；撤销说明改为“阻止后续访问，已加载/复制内容无法召回”，如需更强控制再增加短会话和心跳校验。

### 4.9 审计日志

已操作：事件搜索、类型筛选、状态查看、完整性验证、CSV 导出。

有效之处：追加式哈希链校验为 100%，成功、拒绝、取消和需复核状态均能记录；导出后也会产生审计事件。

阻断问题：服务端 `/api/audit` 只要求 `viewer`，前端也没有隐藏“审计日志”和导出按钮，因此普通只读成员能看见全空间事件。

建议：

- owner/admin：查看并导出全空间审计。
- editor：只看与自己、自己管理的文档/资产有关的业务事件，默认不可导出成员与安全运维事件。
- viewer：不显示全空间审计；如业务需要，只提供“我的访问记录”。
- 服务端和前端同时做权限限制，避免只隐藏按钮。

### 4.10 系统状态与成员管理

已操作：服务健康刷新、运维刷新、创建备份、备份校验、成员邀请、激活、角色切换、禁用/撤销边界。

有效之处：管理员运维台正确只向 owner/admin 展示；备份可以创建并校验；邀请和激活形成真实账号链路。

主要问题：普通成员仍能看到 Same-origin Gateway、SQLite、SHA-256、MinerU/DeepSeek 模型等系统拓扑，第一次使用会误以为需要自己运维。

建议：普通成员只显示“系统正常/暂不可用及影响范围”；管理员默认显示业务化健康状态，把技术拓扑、模型名、数据库和哈希放入可展开的“技术详情”。

### 4.11 移动端

已操作：390×844 视口、打开/关闭导航、从 Agent 切换 Wiki、Wiki 阅读和角色状态。

有效之处：导航按钮可用，切换模块后菜单会收起，Wiki 正文可阅读。

问题：长任务结果在移动端信息密度过高；大量模板、内部编号和多层证据按钮不适合窄屏；禁用按钮依赖鼠标 `title` 的解释在触屏上不可见。

建议：移动端默认先展示结论摘要、待处理项和三条关键证据，其余折叠；禁用按钮旁直接写明所需角色。

## 5. 跨模块优先级

### P0：外部试点前必须解决

| 问题 | 影响 | 验收标准 |
| --- | --- | --- |
| 只读成员可查看/导出全空间审计 | 泄露其他用户、分享对象和运维信息 | viewer 访问 `/api/audit` 返回 403 或只返回本人事件；UI 不展示全空间审计与导出；新增角色 E2E。 |
| 无上传权限时前端假成功并残留旧任务 | 用户无法判断文件是否上传、是否外传，形成事实错误 | viewer 不可打开文件选择；强制请求 403 时只显示中文权限说明；不跳页、不显示进度、不复用旧任务 ID。 |

### P1：正式售前 MVP 前完成

1. 补齐或移除“导入资产/新建资产”空按钮。
2. 修复离线演示字段污染真实上传。
3. 把“脱敏工作台/不可逆涂黑副本”与真实能力对齐。
4. 生命周期分别统计资产待确权和关系待复核。
5. Agent 增加数量一致性校验，统一“已完成/需要复核/确定结论”口径。
6. Wiki 增加差异预览、无变化禁用保存、提交复核流程。
7. 安全分享撤销文案说明无法召回已加载或复制内容。
8. 外部页全中文并增加发送方联系信息。

### P2：提升非技术岗位首次理解

1. “Schema、Reasonix、工具调用、交付门禁、Same-origin Gateway、SQLite、SHA-256”等移到技术详情。
2. 所有指标说明分母、统计时间和下一步动作。
3. 内部资产/证据/任务编号默认隐藏在详情中。
4. 依据岗位提供首次使用引导：管理者看态势，编辑者处理待复核，阅读者查找和核验，外部客户读取交付。
5. 禁用操作提供可见的原因和申请权限入口，不依赖鼠标提示。

## 6. 建议的信息架构

非技术用户第一次进入时，建议按岗位只突出三件事：

| 岗位 | 首页主任务 |
| --- | --- |
| 管理者 | 查看资产与风险态势；处理待复核；查看分享与审计异常 |
| 编辑者 | 接入资料；复核资产/关系；完善并提交 Wiki |
| 阅读者 | 搜索 Wiki；查看原文依据；发起只读核查任务 |
| 外部接收方 | 验证身份；阅读交付；联系发送方 |

系统状态、模型、数据库、哈希、任务步骤等作为二级“运行详情”，不占据默认工作流。
